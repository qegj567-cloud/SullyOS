# 主动消息 2.0「即时对话」方案（instant chat）

目标与红线见 [主动消息 2.0 总纲](../docs/amsg2-overview.md)。

> 讨论稿。定位：把聊天主路径从「浏览器本地跑生成」换成「云端跑生成」，
> 复用主动消息 2.0 已有的整条管线。少写实现，多写取舍——先把方向钉死再动手。

## 一句话

把每条聊天消息当成一条「立刻触发」的主动消息任务：按下发送 = 一次很小的
POST 上云，生成在用户自己的 CF Worker 里跑完，结果走 Web Push 下发。
客户端发完那一刻就自由了——切后台、杀进程都行，回复到了推送会叫它。

## 为什么要做

现状的聊天路径要求**客户端从发送活到生成结束**，由此背上三个包袱：

| 包袱 | 现状 | 改完 |
|------|------|------|
| fire_pack 补传 | 打脏后微任务内立即上传，同一轮的连环打脏合并成一次 | 即时对话这条路用不上——上传发生在按发送那一刻，前台必然可见；机制本身留给本地生成那条路 |
| presence 心跳 | 生成期间每 15s 两个请求，请求数正比生成时长（等 2 分钟 ≈ 20 个请求） | 即时对话这条路不起心跳——worker 自己知道这轮在跑；本地生成那条路照旧续租 |
| 生成期间被杀 | 切后台几秒就可能被杀，这轮白等 | 无所谓，云上照跑，回来收推送 / 拉收件箱 |
| 走 Deno 门面的额度 | 未验证组织 1 万请求/月 ≈ 每天 17 轮（按 2 分钟生成算） | 每轮 1 个请求 ≈ 每天 330 轮 |

这个方案让走即时对话的聊天把包袱直接卸掉。

## 设计要点（高层）

1. **触发**：新端点，POST 带上增量消息 + 本地游标（最后一条消息 id + 条数），
   worker 回 200 = 已受理，几十毫秒的事。门面的 105s 首字节、SSE 送达判定
   那些约束全都不再适用——没有任何一条长连接。
2. **生成**：先落盘再开跑，双保险。POST 把一条 `messageType: 'instant'` 任务写进 D1
   （落盘即受理），上游落库后叫醒起跳器（Durable Object，导出名 `InstantTickDO`，
   类是上游的 InstantTick，一条任务一个实例），由它的 alarm 在独立的调用里马上跑生成；
   alarm 没跑成或中途被回收的话，cron 下一分钟捡起仍 pending 的行接着跑。起跳器和
   cron 抢同一份租约（认领时刻超时才允许另一方接手）防双跑。体感：alarm 跑成 = 秒开跑，
   没跑成 = 最坏 +60s，正确性两头都兜住，不依赖对平台行为的预判。
   生成不挂在 `ctx.waitUntil` 上：它只有 30 秒，一轮带工具循环的生成会被砍在半路。
3. **生成管线**：复用主动消息 2.0 fire 现有那套——工具循环、表情包、
   实时世界、后台 MCP 都是现成的。**这次 POST 顺手把 fire_pack 也更新掉**，
   到点的定时任务和即时对话共用同一份上下文，即时对话这条路才不用再补传。
4. **送达**：Web Push（CF 直发手机，不过门面）。通知一定弹，但同一个角色折叠成
   一条，用户看着页面时不响、切后台照常响铃；消息本身照旧由 SW 转给页面上屏；
   推送丢了靠上线拉收件箱兜底
   ——收件箱进来后那条 13 步后处理管线是现成的，记忆宫殿等本地后处理照跑。
   上屏体感不变：管线对「刚送达」的消息保留拟人打字节奏（每条气泡之间
   0.5~2s），只有补收（躺超过 2 分钟）才一次性回填，和现在的前端一致。
5. **状态**：D1 存对话历史，但**本地仍是唯一真相**。每次 POST 只传增量，
   worker 用游标对账，对不上（回滚备份、删改消息）就要求整包重传，
   重传走 gzip 上行（大 body 42s 超时的教训已有现成修法）。
6. **失败**：云端生成失败推一条 `messageKind: 'error'`（SW 已有这条分轨）；
   客户端「正在输入」有超时兜底，到点提示失败、可手动重发。

## 已经定下的取舍

- **无流式**。生成期间没有逐字吐出，配「正在输入…」指示：POST 200 亮起，
  push 到达熄灭。等不到就每 60s 去云端点名问一次那条任务的状态，只有云端明确
  说它已失败（或那行没了而回复也取不回）才熄灯、提示可重发；生成失败不自动
  重试，云端还在运行或补推已生成的回复时继续等。回复到端后按打字节奏逐条上屏（见上），体感更像真人回消息。
- **通知一定弹，打扰靠折叠 + 按可见性静音压**：同一个角色在通知栏里只留最新
  一条（同 tag 互相覆盖）。响不响由 SW 收到推送那一刻的窗口可见性定
  （`silent: 'when-visible'`）：用户正看着页面就安静躺着，切后台、锁屏则照常
  响铃震动。同 tag 默认是静默替换，所以每一轮的第一段带 `renotify`，一轮响一
  声、后面几段安静更新内容。订阅是按 `userVisibleOnly` 建的，收到 push 却不弹
  等于跟浏览器违约——Firefox 按配额把订阅退掉、iOS 过了新订阅的几天宽限期一条
  就吊销，两边都静默发生。所以口径是：要推就一定弹，不想弹的内容压根不发推送、
  留在服务端收件箱等客户端上线补拉。
- **不做静默兜底**。显式开关，关掉回本地生成。POST 失败 = 这条没发出去，
  明确报错、可手动重试，绝不悄悄转回本地跑——静默分流那种查无可查的坑
  踩过一次就够了。用户自己没开 2.0 时直接走本地；云端跑不了这一轮时转本地，界面标明
  「本机生成」并留 trace。认哪几种情况见[总纲「回退本地」](../docs/amsg2-overview.md#回退本地)。
- **聊天 API 凭据常驻云端**。AI 模式定时任务本来就这样，即时对话只是让
  每一轮都用它，不是新增暴露面。
- **单用户、单设备假设不变**。
- **开关前置条件**：推送权限已授予才允许打开（不然发得出、收不到），
  没给权限时开关置灰并说明。
- **一次做完整替换，不分阶段发**。amsg2 整条链路已经端到端验证过，
  没有需要分批探路的未知数；下面的施工顺序只是干活的先后，不是一个个
  可发布的里程碑。

## 施工顺序

1. worker 侧通道：新端点 + instant 任务行 + 起跳器 alarm / cron 双保险 + 认领防双跑
2. 对账与并轨：游标 / 全量重传（gzip）/ fire_pack 由这次 POST 顺手更新；
   即时对话路径不起 presence 心跳、不走 fire_pack 补传（两套机制留给本地生成路径）
3. 前端切换：发送路径改走 POST、「正在输入」指示、通知折叠与静音策略
4. 收尾：设置页开关（含置灰）、文档、埋点

## 待查小项（不挡工）

- 已定：群聊不切（收件箱按 charId 路由，群聊没有 charId，见契约「群聊不动」条），继续走本地生成
- 已定：即时对话是聊天上云的唯一路径。
- 那条折叠通知在 iOS 真机上的观感：前台聊天时（该安静躺着）和切后台时（该响铃叫人）
  两种情况都要看，另外确认 iOS 认不认 `renotify`——不认的话新一轮的第一段还是会被
  当成静默替换

## 明确不做

- 流式吐字（沉默期由「正在输入」承担）
- 任何静默回退本地的逻辑
- 多设备同步

## 2026-10-01：停止当前回复

生成入口在本地生成、instant 待收期间切换为停止。停止不插入系统消息，也不增加聊天消息类型：保留已经提交到界面的气泡，丢弃尚未显示的正文；流式预览只把停止当刻已经显示的安全正文保存成普通文字。翻历史不会撤销已经显示过的气泡。

职责边界：

- 上游 `amsg-server` 负责取消任务、终止模型请求和工具循环、拒绝后续工具调度/结果投递，并清理未投递 outbox。取消通过租约心跳传播，本应用配置 `leaseHeartbeatMs: 1000`。
- SullyOS 负责按钮、显示进度、落库边界、本地工具的取消信号，以及按 UUID 持久化停止记录。迟到推送和补收只销账，不重放正文、工具或情绪结果。
- 应用 Worker 把上游的 `ctx.signal` 传给 MCP/搜索/日记/小红书与情绪评估，取消异常不能转成普通工具失败后再让模型续跑。`onFireSettled.status === 'cancelled'` 不写生成失败提示、不把未显示全文记成已经说过。

发送前由客户端确定 UUID。POST 尚未返回时停止，先记本地停止记录并取消；受理结果返回后再次取消，覆盖“第一次取消时任务尚未建行”的竞态。独立的 `chat_stop:<uuid>` 回执使晚建行在开始生成前也能被应用 Worker 跳过。

云端 self_log 条目带 `taskUuid`。停止回执只保留已显示的文字，后续读取 self_log 时按回执校正；回执也随下一次 fire_pack 上传，避免取消请求与下一轮生成并发时读到被丢弃的半段。停止不回滚已经完成的外部副作用；AbortSignal 只能中止仍可取消的请求，并阻止后续动作。旧 Worker 需要更新应用 bundle 才有云端执行链取消能力。
