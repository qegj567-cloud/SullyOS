# SullyOS Discord 社区规则

## 社区、招募与维护

糯米机的答疑和官方活动都在 Discord（DC）社区。还没进社区，去小红书搜作者「糯糯糯糯五」，看当期招募公告，按公告里的方式加入。作者定期开放入口；如果这期已经结束，可以等下一次。进群后，在 SullyOS 区的「Bug反馈与疑问咨询」搜索已有帖子，仍有疑问就在这里发帖。糯米机由条和 TO 共同维护，主动消息系列由 TO 完全负责。

在 DC，Sully-08 陪大家玩，Sully-09 负责维护社区，Sully-10 是看大门的社区答题猫。小手机「使用帮助」里负责答疑的是 Sully-11。

这里欢迎使用交流、Bug 反馈、功能讨论、角色卡 / repo / 美化分享和 AIRP 创作交流。这里是兴趣社区，不是客服中心、作者私聊、情绪发泄区或圈子吵架区。维护者、创作者和分享者均为自愿参与交流的普通用户，不承担持续答疑、陪同排查或回应所有意见的义务。

## 去哪个频道

- 「repo记录」用于记录自己玩糯米机的日常，是 repo 即可。「邮局repo区」用于互相打捞、分享匿名信。
- 小手机原生内置功能的使用问题与 Bug 反馈只在 SullyOS 区的「Bug反馈与疑问咨询」发帖。先看使用手册 App、更新说明并搜索社区，仍无法解决再发帖。其他作者帖子下与其作品直接相关的问题依楼主声明。
- 「玩法交流区」用于用户间交流新玩法，比如如何让角色更开放、世界书怎么写。不支持许愿；作者对独立模块明确开放许愿时，可到对应频道参与。「关于捏脸系统的讨论」可以反馈希望增加的发型、服装、部件。
- 「个人碎碎念」是作者自己聊天的地方。「二改交流区」供二改作者分享记录与心得，细则见「社区须知（必读）→ 二改须知」。「永恒浏览器分区」由该浏览器作者七六自治。
- 资源分享区：「角色卡分享」收原创角色卡，请用糯米机专用格式导出，提前标注性向。「美化分享」收糯米机相关原创美化，注意图片来源与版权。「指令世界书-好东西分享」收其他相关原创指令；「表情包分享专区」收糯米机格式的表情包。

## 怎么反馈问题

参与讨论需有基本 AI / API 使用常识，会阅读教程、搜索已有内容，能初步区分 SullyOS Bug、API 报错、模型问题与个人配置问题。

确认需要发帖时，尽量一次写清使用版本、机型、哪个功能、做了什么、预期输出、实际输出、能否复现、使用的 API 模型，以及已自行排查过什么。描述模型名称即可。

第一次发帖也可以只用自己的话写清现象。拿不准是操作问题还是 Bug，都可以在这个区问。11 号建议你来时，可以这样开头：「11 号建议我来问。我在【功能】点了【按钮】，原以为会【预期】，结果看到【现象】。我试过【步骤】，现在还是这样。」贴之前换成自己的情况；与模型无关的问题不用硬填 API 信息。

## 角色讨论、内容与创作

仅讨论正在手抓糯米机内使用的角色，原创、同人、酒馆角色均可。不要讨论各圈子的争议、立场或矛盾；同担、梦向等问题请自行避让。Discord 社区内 NSFW 内容请打上剧透。

禁止 API 贩售、共享账号、魔法等内容。禁止宣传、引流、拉踩其他免费小手机项目（避雷除外），以及引战、挂人、人身攻击、恶意比较和发布影响社区秩序的内容。GPT、Claude、Gemini 等商业 AI 产品的讨论不受限制。

欢迎 Fork、二改与创作，须遵守项目协议、尊重原创，不搬运素材、不将他人成果据为己有。项目使用、传播与二次创作权限以项目许可证及《二改须知》为准。有关边界和二改问题可私聊发布说明的作者。

## 禁言、封禁与申诉（8 月 21 日管理规则）

- 在「Bug反馈与疑问咨询」以外的区域提问小手机原生内置功能使用相关问题：禁言 3 天。
- 一周内累计 5 次以上无效反馈：禁言 7 天。包括未阅读已有提示或教程、明显属于 API / 模型问题、缺乏基本排查、重复提交已得到说明的问题等。
- 明显 KY、持续越界交流或对创作者造成明显困扰：禁言 7 天。管理员结合具体语境、行为频率、沟通经过及实际影响判断。
- 引战、人身攻击、挂人或将外部纠纷带入社区：视情况禁言 3～7 天。正常观点分歧不属于违规。管理员要求停止后仍继续扩大争执的，将进行处理。
- repo、资源分享、二改等创作区域实行楼主自治。楼主可以声明不接受提问、建议等互动；遇到持续影响正常交流的情况，请直接私聊 @Sully-09 反馈。
- 抄袭、恶意盗用、明确的未授权二传、恶意规避管理等严重违规：直接封禁。

未能列举的情况由管理员结合减少无效资源消耗、保护正常创作交流、维持秩序的原则处理。对处理结果有异议，可私聊管理员说明情况，请勿在公共区域围绕处罚结果继续争执。

## 高消耗反馈与冷却期（7 月 10 日说明）

以下行为会被视为高消耗反馈：

- 短时间连续提出多个低优先级问题，如 UI 细节、字体位置、个性化需求、模型输出风格、单机型体验差异。
- 一个问题刚结束就接下一个，要求维护者长期连续答疑、陪同排查。
- 已说明「暂时无法解决 / 不在计划内 / 建议不要使用该功能」后，仍围绕同类问题开启新排查。
- 反复把特定 iOS 机型、个人 API 站、Cloudflare 中转、模型输出异常、个人配置等环境问题转为公共问题。
- 用 AI 生成的分析要求维护者继续阅读、判断、陪同讨论或逐条回应。
- 单条看似合理，整体持续占用答疑资源，影响开发与社区秩序。

管理员会先提醒并要求进入反馈冷却期。冷却期内仅允许反馈恶性 bug，例如无法启动、数据丢失、严重崩溃、核心功能完全不可用。若提醒后仍持续出现高消耗反馈行为，视情况进行 24 小时至 7 天的小黑屋处理。请优先读文档、搜索已有讨论、整理后集中反馈。

## 免费创作与赞赏（7 月 11 日说明）

「赞赏」是自愿、无附加条件的支持，不对应专属功能、额外内容、优先服务、指定修改或差异化待遇。社区说明中，赞赏不构成购买、委托、雇佣、服务合同、投资或共同经营关系。

赞赏不改变项目开源发布、免费获取与使用的性质，也不使项目成为付费行为的赠品。作者自行决定创作方向、维护计划、更新频率及是否回应建议。公开作品可以被评价；赞赏不会增加作者接受批评、回应意见、采纳修改的义务，也不构成将作者或项目拉到其他社区集中评议、要求自证或接受额外审视的依据。

社区不认同作者接受赞赏后便应接受额外忠诚、服从、自证义务，或其动机、作品性质、个人立场便应受到额外审判的观点。不认同上述边界的用户不适合参与本社区。

## 源码、项目链接与公益站自证

按项目开源协议，源码本身可以查看、使用和分享。社区不会将单纯的源码截图、仓库链接传播认定为违规。后端资源、公共服务容量和维护精力有限，作者现阶段不希望大家主动传播源码仓库或项目链接，也希望使用者主要来自社区内部。这是对传播范围的意愿，不是开源协议的额外限制；正常私下交流、社区内部讨论和必要的信息分享不受影响。

类脑公益站管理需要验证小手机无盈利时，可以私聊管理提供链接作证明。可先说明「叫糯米机的免费小手机，开源无盈利，可私聊提供链接证明」。使用公益站请遵守该站规则，不要随意点击 API 的测试连接。部分公益站对小手机类目有自己的态度，留意场合。
