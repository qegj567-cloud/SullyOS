# 可布置的 3D 小屋

## 多人共同生活与串门（2026-10-26）

正式入口、逐角色 API、共同事件与独立记忆、通讯录关系、预约来访和恢复边界见 [多人家园与串门](./room3d-social.md)。执行与验收记录见 [清单](../plans/home3d-social-implementation.md)。

## 换房与装修的家具姿态清理

切换房间或进入装修时，同时清除当前操控者及交换控制后暂存居民的床位、坐位、家具动作与姿态，恢复站姿并重新找落点。不能只清当前 `visitorSeat`，否则用户小人的 `parkedSeat/parkedPose` 会把旧卧室躺姿带到新房间或装修后的空地。无家具活动的正常过门行走保持原有路径。

## 家园设置与成员头像层级（2026-10-11）

编辑器的 `.h3-sheet`（配色、画质等面板）统一使用层级 30，高于成员／宠物头像栏和场景控件，避免关闭按钮与面板选项被遮挡。小手机入口位于编辑器隔离层级之外，面板存在时隐藏，关闭后自动恢复。此调整不改变头像定位与宠物入口功能。

## 清晰画质与顶部空间（2026-10-08）

手机清晰档继续使用最高 3× DPR，人物、五官、家具主画面不降分辨率。柔光只在半宽半高缓冲区做八点亮部采样，再与完整分辨率原画合成，不重复绘制房间几何。缓冲区随尺寸变化释放重建。衣物动态贴合只比较实际有衣物权重的骨骼在胸部坐标系中的变化，整个人的移动、旋转、缩放不触发重新生成接触表面；衣领绑定到头部时仍正常跟随转头。

正式家园顶部增加「画质」入口，画质档位移到设置弹层最前面；本机首次进入弹出简短提示，可直接打开设置，不自动改用户档位，确认按设备保存。3D 场景从容器顶部开始，顶栏、地图和成员头像仅消费一次共享 `--chrome-top`，取消外层顶部 padding 与内层安全区重复叠加；保留状态栏、刘海和原有底部安全区。此修正针对 APK 家园顶部留白反馈，真实设备仍需复核。

## 正式入口 · 拜访（测试版）3D

### 入住形象与日程位置

`Home3DSetupEntry` 在定义后检查双方 `chibiStudio.home3D.state`，没有则引导进入手办柜确认形象；旧小小窝/彼方 state 可作为捏人底稿，不自动当作已确认的家园形象。无布置时先创建并保存原有默认房屋，让日程使用稳定的房间 ID。

手机局域网 HTTP 下没有 `crypto.randomUUID()`。房间与家具统一通过 `model.uid` → `utils/localId.js` 生成本地编号；宠物、家园记录、主动搭话、秘密任务与滤镜预设也使用兼容生成器。选择初始房屋配色会创建房间和家具，须覆盖无 `randomUUID` 环境下的五种配色入口（`homeOnboarding.test.ts`），不能仅测试捏人入口。此工具只生成记录编号，不用于密钥或鉴权。

编号模块导入显式写 `.js`。开发时若改过模块扩展名，Vite 运行中的依赖图可能仍保留旧路径；需重启同一测试服务并刷新页面，不能只用生产构建成功作为恢复证据。`test/fixtures/home-setup.html` 使用真实懒加载入住入口和配色创建回调，结果仅保存在页面内存，供局域网浏览器验收。

日程开启时，按角色时区读取当日日程；无日程、缺少位置或房间已被删除时提示「重新生成并补全位置」。用户点击才调用一次 API，成功后替换今天日程并刷新主动消息快照；失败保留原日程，可以重试或本次先进入。关闭日程不读取、不生成；完整有效日程不重复提醒。

`ScheduleSlot.homePosition` 为 `{kind:'home', roomId}` 或 `{kind:'away'}`，保留 `location` 可读地点。已定义且拥有实际房间的家园角色，生活系和意识流生成都要求每条带位置；模型漏填/返回未知房间 ID 时整份不落库。不用活动关键词猜位置。未建立家园的角色继续原日程格式，旧存档兼容。日程卡展示位置并允许修改；聊天修改活动仍清除旧活动附属地点，下一次进入家园提示补全，避免沿用错误房间。

位置、自动活动、记录、家园交流现已贯通。当前九项交付、验证与边界以 [共同生活闭环](./room3d-life.md) 为准。

### 首次进入 · 家园定义

正式拜访入口通过 `Home3DEntry` 先检查当前角色的 `homeDefinition`。未设置时须明确选择「现实中的家」「连接两个世界的家」「AI 的虚拟家园」，可填写最多 2000 字补充设定，确认后进入。未选择可返回；已有房屋布置不受影响。进入后「家园设定」可修改或取消，取消不保存草稿。定义按角色保存，随完整角色备份保留，角色卡分享/导入剥离此私人字段。

第二种不默认角色知道自己是 AI，也不预设梦境、传送门等解释；第一种不默认同居。三种文案与类型集中在 `homeDefinition.ts`。保存后由 `ContextBuilder.buildCoreContext` 经 `utils/homeDefinitionContext.ts` 注入常驻「你们的家园（共同空间）」背景，包含所选定义和补充设定；下次正常调用生效，保存本身不触发 LLM。不依赖彼方开关，未设置或无效定义不注入，延后易变上下文的聊天路径也保留此稳定段。现实/跨世界模式不引入 AI 身份；虚拟模式明确 AI 身份。说明不代表当前在家，也不虚构已发生的经历。家园动作和对话事件也已接入独立上下文来源，见 `homeActivityContext.ts`。独立素材/动作预览仍可直接使用 `Home3DView`。

RoomApp 的第三分区现为「拜访（测试版）3D」，在角色列表点选后直接打开 Home3DView，不先打开 2D 房间或触发其生成 API。使用该角色的 home3D 保存布置，读取手办柜形象，沿用完整家具、扩建、光影和多人动作面板。退出回到拜访列表；跨应用的 home3D 启动意图退出回桌面。原 2D 房间内的临时 3D 按钮已撤下，3D 返回按钮统一为「返回」。小小窝和世界家园保留原入口。

原「像素家园」移至记忆宫殿 → 角色页 →「像素家园」第二页，与「记忆房间」并列；懒加载原 PixelHomeView，原 IndexedDB 家具/素材/人物/主题继续按角色 ID 读取，没有复制或迁移存档。尚未启用记忆宫殿也可使用像素家园；返回恢复该角色的记忆房间页。完整集成预览为 test/fixtures/home3d.html，追加 ?app=memory 可查看记忆宫殿入口。

## 2026-10-02 · 确认动作实装

以用户第二份 JSON 选单为准：**39 个动态动作（18 组成对、21 个单人）+ 14 个静态拍照姿势**。冻结清单见 `art/chibi/motion-sources/home-approved-selection.json`。拍照姿势暂存，未接入拍照玩法。

正式小屋右上角「一起玩」接入 `HomeSocialPanel`：可以邀请保存过彼方形象的 user、保存过手办形象的其他角色；选主动方/回应方，全场统一 Chibi 或二号素体，邀请者可各调 80–125% 身高。最多四位同时在场，任意一位可做单人动作，任意两位可做成对动作，其余保持独立状态。居民、动作和临时道具不写入房间布置存档。

分类：招呼与示好、聊天交流、关心照顾、亲近陪伴、玩闹活动、闹别扭、自己的小动作。单人拳击仍是练拳；亲密拥抱、摸头、摸脸没有确认素材，不补造动作。原家具活动及早先确认的行走素材不属于这次丢弃范围。

`build-selected-motions.mjs` 仅转换已选文件：统一 rest-space 骨架映射、30 fps 四元数轨、共用原时间轴和根位移。各对角色共用同一个源空间缩放，二号素体在原骨长上做手部接触校正、足底防下穿、大头间距与搭肩躯干倾斜约束；Chibi 用源手轨驱动浮动小手。手机、汽水为动作期间的纯几何临时道具。角色帧完成后刷新衣物与蒙皮包围盒。

动作包在 `public/room3d/motions/selected/`，39 项按需加载（约 9.9 MB JSON 总量，不塞入首屏脚本）。同目录保留 CMU 许可、Hanami 完整 NOTICE、来源 URL、SHA256 和修改说明；不能统称 CC0。源文件仍在忽略目录 `output/social-motion-intake/`，未选的 482 个文件/约 97.6 MB 已删除，AIRYAA Hug Me 与未选候选不再展示。下载脚本只恢复确认源与许可，静态姿势包只解出确认的14个。

运行时：只允许一个会话；加载中取消不会复活旧动作。结束/停止保留当前站位，换素体、布置、总览、换房、家具活动或离开页面取消动作与临时道具。正式小屋在启动前检查接近段、完整根轨与旁观者占位；空间不足明确提示，不穿家具去硬播。此阶段尚不是自主社交 AI，也没有通用衣服/头发精确碰撞；不同自定义衣物仍需视觉检查。

### 头大小 / 身高（2026-09-18）

新模型在小屋「调整比例」及捏人器「3D 调整」提供两个独立拉杆：头大小 75–140%，身高 80–125%，100% 为卫衣参考比例，默认头大小 104%、身高 100%。头大小同步缩放头、脸和所有发片；身高改变颈根以下的身体高度，保持头部尺寸，骨架绑定点和卫衣同步适配。坐垫接触面独立于身高，动作仍只旋转关节。原版体型不应用这些参数。

`HairSettings.headSize/bodyHeight` 随现有本机 3D 草稿保存，缺省/非法值回退头大小 104%、身高 100%，越界值钳制；重置比例也回到这一组默认值，已有手调数值保留。拉杆沿用一次拖动一次撤销、重做；「重置比例」只重置这两项，全部重置仍走现有捏人器历史。预览沿用 120ms 合并更新，调整时保留旧小人至新模型准备好，不重建房间；只调比例时保留动作、位置及坐位。居中近看的镜头重新适配角色轮廓，手动调整镜头后不强制跟随。

## 源文件与生成

`art/jellyfish-home/export_kit.py` 从已有 Blender 场景提取模块，按资产内的材质合并静态几何，保留水母动画节点。输出 `public/room3d/kit.glb` 和 `catalog.json`。Blender 是资产制作端，Three.js 是实时显示与交互端。

目录中带 `url` 的家具使用独立 GLB，加载时按目录宽度归一化并将底部对齐地板，继续共享模板几何和材质。导出器保留这些外部条目和文件，避免重新生成 kit 时丢失沙发。

`apps/room3d/model.js` 管理纯数据和碰撞约束；`editor.js` 管理渲染与编辑；`Home3DView.tsx` 连接 React 生命周期和角色保存。

## Chibi 入住

`apps/room3d/chibi/` 复用发片小人的 FBX 素体、原图分层与动作。`Home3DView` 优先读取 `chibiStudio.room.state`，没有时读取 `vr.state`，并解析本机自定义部件。隔离捏人器渲染副本还原选件与配色，禁止草稿写入；上传的单张成图没有分层，需先在手办柜保存一套形象，不自动随机替换角色。

小人与家具共用 renderer；进入当前房间时根据家具的碰撞盒寻找空地，总览隐藏小人。满房无空位时提示收起家具。动作面板提供两款挥手、睡觉、生气和晃动；省电档手动动作播放 4.4 秒后停绘，均衡/清晰继续播放，减少动态效果仅展示静态姿势。点击空地可寻路移动，「小人」面板提供当前所在区域的门通行按钮；暂不自主跨房间选择活动，动作和行走位置不写入房间存档。

「小人 → 找个位置坐坐 → 花瓣双人沙发」将小人放入已校准的左/右坐位，单人款居中；仅最底下左右脚尖稍微前伸，下半身保持原形，小手刚性平移/旋转。`catalog.seats` 保存家具局部支撑面坐标与朝向，`seating.js` 跟随实例平移/旋转；`visitor.seatOffset` 按坐姿实际下表面校准，避免腿脚埋进坐垫。动作与姿势分开：挥手、生气、晃动、打瞌睡保持坐位，「坐好」回到安静坐姿，「站起来」才回地面；收纳、移除座椅或切换房间释放坐位，总览暂时隐藏。坐位占用属于临时状态，不保存为外观或布置。当前只支持一只小人手动试坐；未配置坐位的旧椅子不自动套用。

3D 发片支持「贴头包裹」和「向外伸出」。后者保留完整画布的 x/y 坐标及顶部轮廓，只添加浅弧度，不沿头壳收拢。`chibi/types.ts` 的 `builtinHairModes` 按具体素材 ID 标记已核对的发髻、马尾、猫耳；手动 `assetModes` 优先于内置分类，不按 back2 整栏套用。额外上传发片的分类随该层保存。3D 调整提供 40 步撤销/重做，滑杆单次拖动合并为一步；全部重置清除尺寸、手动分类和额外层，恢复内置默认，可以撤销。选件本身仍由原生捏人器管理。

伸出发片支持 `puff`：透明轮廓的距离场控制前后两面，中间鼓起、边缘收薄，独立的啾啾分别归一化；透明区不填充。`offsetX` / `offsetZ` 为所有发片提供左右、前后平移。捏人器的隔离副本还提供选件与配色的撤销/重做，不修改原始 2D 捏人器文件。

面板保留「前后位置」，移除「离头距离」滑杆；旧距离参数及额外层的默认外圈间距仍保留以兼容已有外观。衣服 / 外套在合成前分别从各自不透明上沿调整长度（0–2），不再提前合并；未覆盖区域以肤色打底，背面只延续有衣料的行。`test/fixtures/chibi-clothing.html` 验证独立长度、前后露肤与零长度。

小人素体按材质合并索引分组，避免每个三角形单独绘制。3D 捏人预览复用 WebGLRenderer，静止停绘、动画最高 30 帧，缓存补片取色与透明轮廓距离场；编辑时暂停背后的房间。`test/fixtures/chibi-performance.html` 检查静止帧数、调参画布复用和绘制提交量，当前测试形象为 21 次提交（不代表所有造型或设备帧率）。

`chibi-experiment.html` 直接预览组合场景。「捏小人」包含原生选素材与 3D 调整页签；切入 3D 时捕获当前编辑的分层，不重新随机。四种头发分别调长度、宽度、上下位置与离头距离；最多六层额外发片可以复用后发或上传透明 PNG/WebP，并作为完整外圈薄层渲染。确认后将调整应用到房间，实验形象与参数分别保存到 `chibi-world-experiment-appearance` / `chibi-world-hair-settings`，暂不写入角色正式存档。`test/fixtures/chibi-layers.html` 检查原生 Roll 与 savedState 还原后的各层一致性；房间测试包含初始家具空地及满房拒绝落点。

独立预览：运行 `node art/jellyfish-home/editor-build.mjs`，再运行 `node art/jellyfish-home/server.mjs`，打开 `http://127.0.0.1:4178/assets/editor.html`。预览存储与应用角色数据分开。

### 柔和日光微调（2026-09-16）

基础照明使用冷色天空/蓝紫地面环境光、暖色开放侧补光与较弱蓝色侧补光，减少平均发灰。窗光是有窗房间唯一投影主光，开放侧补光不再向窗户后方投出第二组矛盾阴影；无窗房间的桌面均衡/清晰档启用 1024/2048 主光缓存阴影。阴影采用 PCF，取消 VSM 模糊通道。人物及手持玩偶不投射动态阴影，延续插画人物的无自阴影处理。布局、家具拖动、房门/冰箱门开合、玩偶拿起/归位时显式更新缓存；人物走路和镜头缩放不重绘静态阴影。

白天/夜晚窗户采光使用固定两盏可复用聚光灯池（清晨/夕阳改用下文的定向太阳光）：清晰桌面最多两扇外窗，省电/均衡/触屏/手机最多一扇，总览关闭。`windowDaylight.js` 负责真实外墙和同层细绘区域筛选、朝向及房间坐标换算；`windowDaylightLights.js` 共享一张 128² 程序四格遮罩、每灯 512² 缓存阴影。光照落在实际床、桌、地面上并受家具遮挡，不是贴地光斑。内墙窗不产生室外日光；隐藏墙面不会关闭物理存在的外窗光。`windowSky.js` 在已有玻璃几何上绘制亮蓝天空、暖色地平线和淡云，不增加网格、图片纹理、后处理或逐帧动画；不改镜面及其他玻璃物件。卸载时释放灯池阴影和遮罩。

### 手机端容量

手机浏览器每个角色最多 6 块原始房间面积，与六房间初始住宅一致。布置不再用 20 件作为空间判定：`furnishingSpace.js` 复用小人的行走碰撞图，以 0.4 格网格检查可站立空间与原有可行走区域是否被新增家具切断。小玩具、桌面摆件按实际碰撞空间处理；已阻塞的旧布局可以继续整理。此检查是通道保护，不是自动布局设计，也不保证每个动作的接触点都可达。

每块地板另保留 80 件的手机绘制保护上限，按物件实际中心计数；桌面摆件和吸附椅子分别计数，收纳、墙段和边界门不计入。拆墙合并不减少面积块数；原有存档最大容量仍作为结构安全上限。

`deviceBudget.js` 统一计数和限制；新增、复制、套装、恢复、跨区拖动及导入都会检查，整组超限原子回退且不写历史。旧超限布置加载时不删除、不截断，可以继续收纳、搬走或改色，但超限区域不能进一步增加；导入新布置须完整符合手机额度。撤销/重做保留原历史状态。家具架/扩建/房间/装扮显示已用额度。

「房间 → 修改当前房间名称与装扮 → 恢复当前房间初始布局」恢复六房间模板的对应房间及入住色板，也支持新添加的样板房。保留房间 ID、名字、收纳箱、邻房共用墙面、日常记录和宠物；通过原子布局导入与撤销历史完成，不覆盖整屋。已有六房间存档按原始位置识别模板；没有已知模板的扩建房间不提供恢复入口。退出布置时清除本轮提示；家具选中/改色面板显示时隐藏小手机入口。

合影模式的退出按钮显示「退出拍照」文字，消费共享 `--chrome-top` 顶部安全空间；接入局部返回处理，支持浏览器/Android 返回和 Escape。

手机省电档默认仅精细显示当前一间，均衡/清晰按档位预算；保留正在行走/互动所在区域，静止停止绘制，同层骨架保持可见。手机检测依据移动设备标识，或小屏粗指针设备，桌面窄窗口不自动套用手机额度。数量限额不等于帧率保证：面数、材质提交、小人发片和设备性能仍有影响，模拟浏览器测试不代替真机发热/帧率验收。

宠物详情底部提供「移出家园」，确认后删除当前宠物实体并释放名额，保留已有小记。终止这只宠物的接触、待唤醒和需求动作，不补发未完成互动的奖励；其他宠物继续活动。面板提供「撤回移出」，按逆序恢复原 ID、名字、配色、性格、需求和亲密度，恢复时重新检查空地及 7 只上限；条件不满足保留撤回记录供稍后重试。撤回栈仅在本次家园运行期间有效，关闭面板不清除，离开家园或恢复整屋备份后清除；不进入存档与备份，也不改变旧存档结构。移出本身立即沿用家园保存路径落库。验收：room3dPetRemoval.test.ts 与 home-pets.html。

### 秘密小纸条：跟随所属回合与水位线

新秘密只输出一份 `text`，不再输出、保存或常驻注入 `memory`。情绪评估继续与主回复并行；秘密生成后等待本轮主回复成功提交，绑定该轮全部回复消息的明确 ID，再将正文保存为一条 `secret_note` 消息。本轮停止、失败、来源缺失或跨角色时宁可放弃。素材仍限本次允许历史中的已完成对话；生成中的回复不作为事实素材。新纸条属于本次生成的回合，不回填素材所提及的旧回合。

纸条与普通消息共用上下文范围、语义计数、归档和水位线，每张占一条。上下文与总结解析同一正文，附旁白指代和知情边界，不能当作角色已对用户说过的话。并行请求已经发出时无法修改那份请求；纸条提交后，下一次上下文组装即可读取，随后按通常水位规则代谢。日常私聊、小屋对话和小记均不展示纸条，也不占普通聊天的可见分页位置，关闭「隐藏系统日志」同样不会显示。仍只在进入小屋时沿用原有揭晓弹窗；用户主动操作历史记录时，AI 原文读取范围、清理选区和记忆宫殿手动总结选区显示纸条标识与正文/预览，让原始记录数量与水位线对得上。原文范围页的纸条直接在页内查看，不长按跳入普通聊天。

秘密与父消息在一个 IndexedDB 事务里双向绑定。单条/批量删除及区间清理，只要删除本轮任一父消息，就同事务删除整张纸条；小屋投影的移除或改写也作保守失效处理。删除纸条本身可保留回复，重放生成结果及撤销父记录都不会恢复纸条。迟到评估写入前再次读取全部父 ID，不能按内容猜测或绑定到同文的新消息。情绪落库只更新最新角色的情绪字段，不把评估开始时的旧小屋快照写回。

旧秘密不补录历史，旧 `memory` 不进入任何上下文，后续资产状态写入时去掉该字段；旧待完成请求直接放弃。资产中的秘密索引仅供揭晓/去重，带消息 ID 的纸条以消息库为准，删除后不再展示或作为近期创作素材。当前云端即时对话的评估回调没有可证明完整的本轮父消息集合，因此不发起新秘密任务；正常情绪评估照常运行，不能为了留下秘密猜测来源。

回归：`utils/secretNote.integration.test.ts`、`utils/homeSecrets*.test.ts`、`utils/homeContextSegments.integration.test.ts`、`utils/chatHistoryCleanup.test.ts`。

### 进屋纸条弹窗：明确阅读与收起
