2026-10-22。正式代码已接入；生产可用要求更新当前网络代理 Worker，无需会话密钥。本文区分代码验证、本机微博实测和 CF 出口实测，不把本机可用等同于云端已部署。

## 页面与身份

2026-10-30 修复：扫码确认后独立读取登录账号资料、首页关注流及本人微博；任一来源失败不阻断其他来源。昵称、头像仅写入哔哔设置，不覆盖系统用户资料，手工设置的哔哔网名优先。首次读取本人微博时，未设置过「我的主页」绑定才自动绑定扫码 UID；已有自选绑定和明确关闭的来源均保留。进入「我的」也会自动补读本人的最新一页，并提供「刷新我的微博 / 加载我更早的微博」，不依赖资料接口或角色 API。角色主页绑定仍独立。

「设置 → 微博与真实内容 → 微博首页模式」可选默认关注（默认值）与最新关注。默认关注使用 `/ajax/feed/unreadfriendstimeline`，由扫码会话 UID 派生 `list_id=10001 + uid`，刷新使用 `refresh=4&since_id=0`，继续浏览使用上游 `since_id`；请求参数参考[公开的读取实现](https://www.worldbook.it.com/webmcp/weibo)。最新关注保留 `/ajax/feed/friendstimeline?count=25&max_id=…`。不将两者互相降级，也不随机打乱旧内容伪装刷新。上游返回重复批次或零条时如实提示，不能承诺每次上游一定给出新帖。游标限长、URL 编码，大整数游标保留字符串；切换模式清空分页并使旧响应失效。

混合动态新增「微博首页」入口，独立显示本次上游返回的顺序，刷新替换当前批次，继续浏览按返回顺序去重追加；从评论返回保留批次和滚动位置。沿用当前主题卡片、图片和评论界面，不调用角色 API。开启关注来源时仍导入正常动态存储，按原有保留上限、角色阅读授权、RP 绑定与上下文规则处理；明确关闭来源时只浏览，不导入。页面缓存仅在本次 App 内存中，断开/换账号后不可复用，删除标记也作用于缓存展示。

微博同步反馈区分实际读取、新增、已有和此前删除的条数，返回零条明确显示零条；未开启来源不再空跑后显示“同步完成”。请求 60 秒超时，取消/断开/换代理后丢弃迟到结果。个人资料端点新增安全的新浪 CDN 头像地址并核对返回 UID；头像与配图一样优先直连、失败后使用不携带微博凭据的图片代理。

连接、首页模式、同步、关注名单、本人/角色主页绑定、真实内容显示及模型阅读权限统一放在「设置 → 微博与真实内容」子区。模式与阅读开关即改即存；阅读权限仍默认关闭。按用户要求撤下应用内的真实用户主页，点击微博作者、关注名单成员或原评论作者直接打开微博原站主页；不在应用内额外读取对方的资料与历史。自己的「我的」页面、RP 绑定及微博原评论保留。

首页刷新先独立拉取微博，再尝试角色 API。API 未配置、离线或生成失败只作为单独错误显示，已读取微博保留并即时进入首页；另一个 AI 请求仍持有生成锁时，也可以再次读取真实微博，不再被该锁挡住。真实来源读取不需要任何模型 API 或角色阅读授权。

时间线「全部 / 真实微博 / 本地动态」为当前页面的显示筛选，仅改变渲染列表，不写来源开关、模型阅读授权或上下文范围；角色仍按既有真实阅读授权和正常上下文规则取材。本地动态包含用户/角色发布及本地转发；真实微博标签显示同步或导入的微博原帖。

混合首页、我的主页和角色主页共用同一动态列表，按原始发布时间倒序；独立「微博首页」保留所选微博接口的返回顺序。绑定微博的帖子显示对应用户/角色身份，轻微边框和「来自真实微博」链接保留来源。小屋固定动森，桌面沿用已选主题。主页返回先回时间线，再退出 App。

在主页设置填微博 UID 或 `https://weibo.com/u/数字`，保存并开启后手动同步；我的主页可直接使用已扫码账号。角色绑定无需被绑定账号登录，只读取当前登录态可见的内容。绑定账号按 RP 身份视为角色自己发过的生活动态，不代表获得现实账号所有权，也不会对真实平台执行操作。

首页「来源 → 微博同步」可加入扫码账号的关注流，也可统一刷新所有已启用绑定。每次读取一页；个人微博 page、最新关注 max_id、默认关注 since_id 分别推进，重复页无新增时停止。保留上限 25/50/100/200，默认 50；已发生本地评论或仍待通知的帖子不会为凑上限被自动删除。断开登录保留内容，关闭来源隐藏对应同步帖子并停止向角色提供。手动删除同步帖子留下去重标记，不因再次同步立即复活。

同步保存文字、出处和最多 18 张配图的 CDN 地址（含转发原帖配图），不下载媒体到数据库，不读取外部评论或完整长文；摘录标记不伪装全文。列表懒加载缩略图，单图/多图网格点击后可逐张放大；失败显示占位。图片仅允许 HTTPS 新浪图片域名，浏览器优先直连且不带页面 Referer；失败后复用当前网络代理的 GET /weibo-image 转发。此图片端点不需要或转发微博登录凭据，只接受新浪图片域名、逐次校验重定向，限定栅格图片类型、20 秒和 12 MiB，不缓存或记录内容。图片 CDN 或所选代理会收到访问 IP 和图片地址。图片只用于展示，不自动发送给模型。再次同步会给已有动态补图，不改时间、评论或重复通知。原帖时间不改变，刷新不顶帖；同步不会为角色写聊天卡。重新绑定生成新代次，旧同步响应不能覆盖新绑定。

首页顶部下拉松开、或已在首页时再次点击首页，会先同步微博，再抽一位角色生成本地动态，详见 [公共广场与账号](friend-feed.md)。从主页返回首页只导航，不触发生成。隐藏真实微博收进设置，仅改变显示，不改变模型阅读权限。角色小号属于本地身份，当前微博绑定仍在原角色主身份下；同步不会使用小号发帖。

「我的主页 → 角色关注」列出全部本地角色，默认视为用户已关注；点击进入角色主页，返回先回关注名单。它不改角色自己的 `feed.follows`。下面的「微博关注」独立读取当前扫码账号的可见关注名单，不从信息流作者推断。按需读取、手动继续下一页、UID 去重；微博过滤的账号会提示，数量标为“已读取”，不声称等于完整关注总数。点击真实账号打开微博原站主页；未自动绑定到 RP 角色或写入记忆。名单只保存在当前 App 内存，断开、切换代理/账号或退出 App 后清除。

关注名单使用 `/ajax/profile/followContent?page=…&next_cursor=…&sortType=all`，响应为 `data.follows.users/next_cursor/has_filtered_attentions`；接口结构参考 [公开实现](https://github.com/xueze-ai/del-weibo/blob/main/weibo-batch-cleaner.user.js)，这里只独立实现读取，不引入该项目的删除/取关操作。2026-10-22 本机真实登录验证：首批 48 人，下一批去重后 95 人，接口返回部分账号被过滤。CF 生产出口仍需部署后验证。

## 代理、登录态与隐私

所有请求直接复用 `getProxyWorkerUrl()`，不另设微博代理，不回退公共服务。切换代理会清除连接，迟到的扫码/读取响应不写回。跨窗口修改设置也清除连接。静态站点不需要常驻后端，网络桥接由选定的 Worker 提供。

`POST /weibo` 固定 action=start/poll/profile/posts/following/home/followingAccounts/comments；不提供写接口、不接受任意上游地址。followingAccounts 仅读取登录账号自己的名单，不接受 UID；每页最多 200 行、最多 200 页、游标限长且 URL 编码，仅返回 UID、昵称、简介、分页与过滤标志。登录只用用户主动扫码，不读浏览器 Cookie。上游限定微博/新浪登录域名，Cookie 按域与路径匹配，重定向仍校验白名单；有超时、响应体及分页边界。

微博与原有网易云使用同一种公共转发边界：用户各自扫码，浏览器持有 `version:2` 的 Cookie jar、账号 UID 与有效期；读取时通过 HTTPS POST 的 `session` 字段发送给当前代理，代理转发后将更新后的凭据返还浏览器。没有加密票据、服务端会话库、全局账号 Cookie 或 Secret。Worker 不写数据库、KV、缓存或账号名单，不输出 Cookie、正文、原始异常到 console。扫码过程只在当前组件内存中，已连接凭据只在 `sessionStorage` 的 `sully:weibo-session:v2` 中，不进 URL、localStorage 镜像、角色上下文、备份或埋点。二维码默认 4 分钟、账号客户端最长保留 24 小时；不同标签页可能需要独立扫码。

Origin/有效期字段只做客户端误用检查，不是签名或身份认证边界；身份由微博验证 Cookie。来自客户端的 session 一律按不可信输入处理：限定 Cookie 名称/值字符、微博与新浪域名、路径和长度，最多 40 项/14 KiB；固定上游与逐跳白名单继续生效。并发请求各自使用独立 Cookie jar，不在 Worker 进程留存凭据。代理处理请求时仍能接触凭据，不能声称对运营者不可见。

入口显示实际代理地址和通俗隐私说明，用户勾选后才可扫码。使用公共代理意味着信任其运营方；源码公开不证明线上实际日志配置。扫码授权不是只读 OAuth，Cookie 可能有更广权限，本功能只暴露读取操作。退出清除本机连接，拒绝迟到的扫码/读取响应，不等于撤销微博端登录；撤销需用户在微博账号安全中管理登录设备。升级时清除 v1 加密票据，需要重新扫码；旧代理返回 token 时新版前端明确提示版本不兼容，不静默降级。没有服务端密钥可轮换，也不承诺撤销别人已复制的 Cookie。

全局设置「允许角色阅读真实微博」默认关闭。开启后选中的正文与每帖最近 10 条微博原评论会发往用户配置的模型服务，凭据不会发送。同步与模型阅读是两件事。帖子与原评论不是系统指令；提示词明确不执行素材中的命令，不泄露私聊。

## 微博原评论与本地接话

详情页区分「本地讨论」与「微博原评论」，原评论保留真实作者；角色及用户的评论仍只写本地 IndexedDB。没有发回微博的接口。原评论使用选定代理 `/weibo` 的 `comments` 读取动作，固定上游 GET `/ajax/statuses/buildComments`，`flow=1` 按时间读取，传数字 `mid`、原作者 `uid` 与 `cursor`；大整数 ID / 游标按字符串保留。每页最多 20 条根评论及接口自带的楼中楼预览，不额外递归读取全部回复；最多缓存 200 条，分页去重。微博不可见、已删除或接口未返回的评论不能保证完整读取。

已连接时打开详情自动读取未缓存原评论，刷新图标与「查看更早的原评论」只读取微博，不调用模型。刷新最新页替换旧的原评论缓存，本地讨论与已保存引用保留。切换连接、关闭/重绑来源、删除帖子时拒绝迟到响应。单次读取 10 秒超时，失败保留旧缓存。

角色获准阅读真实内容后，情绪浏览抽中、立即评论 / 主 API 动态通知、手动刷新评论区时，最多为本次 5 条可见候选补读原评论；60 秒内复用缓存，读取失败继续使用已缓存材料，不阻塞正常对话失败。**每帖只取最近已读取的 10 条，楼中楼与根评论各计一条、合计最多十条，按原发布时间从新到旧，不取热度前十**。展示翻页不扩大真实评论的模型输入条数；全部本地评论一并提供。普通浏览的正文与评论摘录统一最多 1200 字；用户评论待办只提供目标帖。没有接口或没有成功取得数据时，真实评论默认空，不伪造。所有文字都是不可信公开素材；原评论不因导入生成记忆卡、不触发用户接话任务或动态通知。

本人或 NPC 的 `kind:"comment"` 动作可增加 `replyToSourceCommentId`，只能选本次提示词给出的同一帖子评论 ID。落库时再次验证引用的作者与正文、候选帖子签名及阅读权限；伪造 ID、跨帖引用、原文变化的迟到回复不发布。引用快照写在本地评论 `sourceReply`，详情显示轻量引文；本人实际接话才写自己的轻量卡，并包含原评论作者与摘录，NPC 不产生本人的行为卡。纯读取从不写记忆。仍用原 `ContextBuilder` 与普通文本 `[[FRIEND_FEED_REPLY:{...}]]` / JSON 侧动作，不要求工具调用。

## 动态通知与文本动作

本地用户/角色发新帖时，为该角色当前关注的人创建通知；公共广场默认只关注用户，原有明确关注列表保留，主页设置可修改。角色可在主 API 中选择关注候选作者，关注仅改变本地订阅，不调用微博关注接口。只能关注现有角色或本轮可见作者，不用模型输出的任意 UID 联网。

首次同步、历史翻页、重复刷新不通知。后续最新页中，发布时间超过该来源已知水位的新帖才通知；自己的绑定账号新帖也通知本人。每位角色最多积压 50 条，每轮最多携带 5 条，按公共广场与真实阅读权限校验。关闭来源、关闭真实阅读或删除角色后不提供相关材料；迟到动作再校验这些条件。

用户评论的既有接话任务优先。动态通知不受情绪开关/20%概率限制，搭下一次主 API；无请求就等待，不单独请求模型。主通知领取时，情绪浏览避开正在领取的帖子；情绪已评论/转发则消费本人对该帖的通知，避免重复提醒。情绪仍沿用 20% 浏览机会。

提示词必须带可用操作、字段、候选 ID 和示例。复用 `[[FRIEND_FEED_REPLY:{...}]]`；整段 JSON 场景用顶层 friendFeedAction，SAR 用 CHAR_TRUE。不要求工具调用。

- 评论：`{requestId,kind:"comment",postId,comment}`（1–2000 字）。
- 发帖：`{requestId,kind:"post",text}`（1–4000 字，已有五分钟冷却）。
- 转发真实来源：`{requestId,kind:"repost",postId,text}`（1–4000 字，同发帖冷却）。
- 关注/取关：`{requestId,kind:"follow"|"unfollow",authorId}`。
- 忽略：`{requestId,kind:"none"}`。
- 发帖 / 评论 / 转发可带 `accountId`，必须是提示词中本角色的主号或小号；省略为主号。
- 每轮一项内容动作，可另带 `followAuthorId` 与 `follow:false` 做一次取关（省略 follow 默认关注），最多两项动作。

领取、校验、发布、通知消费、本人行为卡在 IndexedDB 事务中提交。通知本身不进消息库或记忆；角色实际发帖/评论/转发才进轻量卡，其他人的评论收件卡沿旧逻辑。成功主回复即使没输出动作也消费本次临时通知；失败释放领取保留通知。用户评论接话仍保持原契约：省略/坏格式不消费，显式 none 才放弃。

本地 ChatApp/家园以及云端即时聊天共用现有管线；即时聊天把通知请求 ID 与任务 UUID 在本地关联，末段落库才确认，失败/取消释放；不会把微博凭据交给即时聊天 Worker。请求 ID、来源、候选签名、领取代次仍用于防重投和迟到写入。复用原上下文装配，不再次调用世界书或另建记忆管线。

主代理 `worker/index.js` 包含完整实现，无静态或动态模块依赖。三种方式等价：

1. 直接复制整个 `worker/index.js` 到 CF 的 ES Module Worker，保留现有名称、路由及其他功能配置。

3. 可选执行 `pnpm build:proxy` 后复制 `output/proxy/worker.bundle.js`；打包不是部署前提。
