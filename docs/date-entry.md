# 传统见面：入口与场次

选择角色后选择「靠近 TA」「让 TA 靠近」「直接见面」，再点「确认进入」，聊天页跳转也走同一入口。

## 雨夜票券入口

底图使用用户提供的雨夜玻璃摄影，来源与许可见 `assets/date/README.md`，通过 Vite 静态导入。票券用静态 SVG 细点纹理替代实时噪点滤镜，去除多重投影滤镜，只保留位移与透明度动效。双层票券边框、缺口、虚线、枝叶／雨伞／水纹图标与装饰曲线均为原生 SVG，文字和控件为真实 DOM；底图只用于界面，不自动成为本场场景或提示词事实。

默认选中「靠近 TA」。点票券只改变高亮并播放抬升、扫光动效，不请求模型、不计开场事件；点「确认进入」才执行所选开场，按钮防止重复提交。方向键、Home／End 可切换选项；尊重减少动态效果偏好。小屏可纵向滚动，三个选项仍并排。顶部齿轮打开见面设置，返回保留当前选择；底部「场景与微调」打开本场体验弹窗，关闭或全局返回只收起弹窗。

顶部标题和返回／设置按钮使用与其他 App 相同的 `--chrome-top` 安全区（缺省回退 `--safe-top`），向下留出操作空间；只调整内容位置，摄影背景仍铺到顶边，不加纯色占位。

## 场景图片与立绘

设置标题只保留中文。背景、默认立绘和皮肤图片共用上传选择器：点击图片后选本地文件或图片链接。背景本地上传保持原画质，立绘沿用原来的压缩与透明通道规则；本地文件仍保存为 blobref，链接仍保存为 http(s) 字符串。

观测协议、行动选择与离开提醒合并在同一张卡片，三行均采用左侧标题／说明／展开箭头、右侧独立开关的格式。展开只查看详情，不改变启用状态；开关即选即生效。「场景与写法」仍在其下方。设置页的总开关、阅读开关、深挖开关及观测维度开关复用细轨道开关，保留至少 44px 点击区、键盘焦点与减少动态效果支持。

「立绘与皮肤」统一展示基础情绪、自定义情绪与套装：自定义套装面板直接列出默认立绘、已有套装与「新建套装」，点选即使用，选中项显示勾选与「当前使用」，无需再次保存。新建套装后直接使用并配置图片；只挂载当前套装的缩略图。添加情绪后直接选择图片；删除自定义情绪需确认，说明会移除默认及所有皮肤的对应配置，保留其他情绪与小小窝 chibi。上传补上未登记的情绪键，沿用现有情绪标签与皮肤选择管线。不会把其他皮肤的图片混入当前皮肤。

继续使用 `sprites`、`customDateSprites`、`dateSkinSets`、`activeSkinSetId`、`dateBackground`，无新表或存储键。个人／全部用户、迁入独立用户、云备份、旧作品与角色卡分享沿用原字段范围；整合备份带本地图片，文字备份沿用媒体剥离规则。媒体补图仅更新匹配角色，沿既有白名单恢复立绘、皮肤及相关配置，不创建新角色或覆盖聊天经历。

## 本场体验与角色默认

三个开场选项共用底部「本次文风」，点击打开自定义文风面板，列出十套名称、文学风格与简短说明，支持关键词搜索（「日系文学」和「日式」可互相匹配）。只切换 style，保留本场基调、场景与补充。面板按需挂载、独立滚动，不使用原生文风下拉，也不加载图片或持续动画；选择即应用，关闭不改选择。入口用深色面板，设置用浅色面板。

「场景与微调」按场景、相处氛围、文风、补充要求直接排列；详细设置把「场景与写法」放在「离开提醒」下方并默认展开，额外直接展示叙述视角。氛围和人称均为可见点选项，人称附例句；此分区仅「我的预设 · 保存与管理」折叠，角色默认保存／恢复操作放在分区末尾。立绘位置调整即时预览、松手自动保存，退出也保留；页面不设统一保存按钮。人称、语音、观测、时间感知与显示方式仍独立，不改变预设存储边界。

入口选择只存在本场内存中；发送、继续、重生成与开场均使用该配置。挂起时与 openingMode 一起交给 SuspendedDate，恢复后沿用；明确结束后下次从角色默认重新取值，刷新不恢复本场配置。会话内「布置场景」的体验修改也仅影响本场；人称及其他个人偏好仍按角色保存。「设为角色默认」行内二次确认后保存，下次进入使用。

角色选择页的设置修改角色默认。预设新增 experience（style、tone、digDeeper、sceneSeed、extra），保留旧 content 字段。没有 experience 的旧预设只替换补充，不重置其他选择；删除预设不清空当前配置。默认与预设随角色个人备份保存，本场临时选择不落库，不随角色卡分享。

「我的预设 · 保存与管理」使用自定义选择面板，不使用原生下拉。列表区分完整体验与仅补充要求，点击即应用；尚无预设时显示创建引导。更新与删除仍沿用原来的二次确认。

## 通道切换与兼容

本轮 DateApp 优化不修改数据库版本、对象表、索引或升级回调。2026-11-28 核对的 master 与 canary 主库均为 74；新增体验字段放在现有角色记录，行动建议放在现有消息 metadata，正文仍使用原先的见面格式。背景、立绘、皮肤、语音、观测和离开提醒沿用既有存储结构。

canary 与 master 共用同源数据。旧版会忽略互动基调、场景、行动建议及完整体验字段；不认识的新文风回退默认写法，不会因此无法开库。旧版更新预设只修改 name/content 并保留未知字段，新版再次应用已保存预设时以兼容字段 content 作为补充正文，避免回到 canary 后读到旧副本。

切换通道会刷新页面；本场临时体验、挂起状态与未发送草稿仍是内存状态，不承诺跨通道恢复。新输入引导复用旧键 `sully-date-entry-guide-v1`，旧版不识别 `input-seen` 时可能再显示一次引导，不影响角色与记录。上述结论仅覆盖 DateApp；发布应基于最新 canary 合入本轮差量，不能拿落后的工作分支直接覆盖通道已有更新。

## 输入框与首次提示

进入会话后背景由用户在角色的见面设置中自定义，未设置时使用原有黑底。雨夜摄影仅用于入口票券界面，不作为会话默认背景；本地演示也遵循同一规则。

进入场次（含直接见面与挂起恢复）默认折叠输入框，已有草稿保留。首次在输入按钮旁显示「点这里展开输入框」，按钮柔和闪烁四次；减少动态效果时只保留文字。展开或选入行动草稿后记为已读，下次不再提示。失败重试仍可展开输入框。

输入提示为「如果留空，则继续当前剧情」，同一按钮有文字时显示「发送」、留空（含纯空格）时显示「继续」，顶部不再另设继续按钮。提交后收起输入框，失败时重新展开并显示「重试」。继续沿用原有调度、记录标记与统计路径，不发送空白台词，也不把留空视为用户同意或选择了行动建议。

输入框右下角的展开图标打开画面中央的大输入框；缩小、Escape、点击遮罩或系统返回恢复底部浮框，草稿保留。展开状态仅在当前页面内存中，不保存为偏好；发送或关闭后重置。长草稿和行动列表仍能滚动，但隐藏原生滚动条，不挤动角色正文。

沿用现有按用户的新手引导键 `sully-date-entry-guide-v1`：`seen` 表示已读入口说明，`input-seen` 表示已完成输入提示且包含入口已读；入口确认不会覆盖后者。备份、跨用户和旧数据沿用该键原有范围，不新增键、角色字段或统计属性。存储不可用时当前页面仍正常收起提示。

## 提示词与展示

### 可编辑行动建议

详细设置的「行动选择」默认关闭，按角色保存，独立于体验预设。开启后下一次开场、回复、继续和重生成在同一次模型请求末尾生成 `⟦ACTIONS⟧` 块，固定 daily（日常推进）、plot（括号申请变数）、joke（插科打诨）、oppose（排斥反对）四类。它们是用户尚未选择的回应草稿，不是已发生的行动，也不决定角色下一步反应。

调用返回后先分离建议，再走原有正文／SAR 管线。正文照旧驱动立绘、语音、观测与记忆；建议存入该条消息的 `metadata.dateActionChoices`，不混入正文历史。缺失或部分格式错误时只展示有效建议，不追加 API 调用，不阻断正常回复。开关关闭时不要求建议，并隐藏已有建议。

阅读模式显示最新一轮建议，立绘模式在本轮最后一行播放完后显示。点击只追加到输入草稿，保留已有输入，用户可修改、补充后手动发送；可收起或重新选择。只使用当前场次最后一条角色回复的建议，用户发送后旧建议失效。行动建议在画面中央独立浮出，绝对定位、不为建议预留正文或输入区高度；长内容在浮层内滚动。点外侧、收起、Escape 或系统返回可关闭，键盘焦点留在浮层中。点选后关闭浮层并打开输入框，输入框同样在底部悬浮，不调整正文位置、高度或阅读页留白；收起后保留草稿。减少动效与原有立绘、语音规则保持独立。

开关随角色的文字／整合个人和全部用户备份保存；建议随消息 metadata 一起备份。迁入独立用户保留，跨空间继承只带开关不带消息经历，媒体包不覆盖此配置。角色卡分享剥离开关。输入草稿仍走原有本场挂起机制。实现见 `utils/dateActionChoices.ts`，不新增存储表或 localStorage 键。

验收：`utils/dateActionChoices.test.ts`、`utils/dateActionChoiceUI.test.ts`、入口／提示词／备份相关回归；`scripts/test-date-actions.mjs` 使用模拟回复检查开场、点选补充发送、阅读切换、挂起恢复、关闭和手机布局，截图只写系统临时目录。

行动浮层与对白、输入框共用黑白细边圆角样式，浅色阅读跟随纸色；列表独立滚动，标题与关闭操作保留。浮层不叠加背景模糊，只做短暂透明度／位移动画。逐字播放由独立文本组件更新，只在开始／结束通知会话；阅读正文、语音行解析、SAR 原文解析及自定义阅读 CSS 校验按依赖缓存，输入草稿不重复解析。保留既有历史分页与离屏渲染；背景只过渡透明度，减少动态效果时直接显示完整台词。

空间基础、角色自我理解、对白表达、用户对关系的理解分开：不把想象空间约定变成角色必须复述的台词，不替用户规定身份与信念，不自动确认为成年伴侣。开场与正式互动共用基础定调和独立的见面回应原则，不改私聊共享原则；见面跳过公共 Anti-Filler，保留可选的素材取舍引导。

十套文风为电影感、简洁白描、细腻文艺、轻快幽默、浓烈炽热、糖浆、棺材边的野餐、潮雨走廊、冷峻正剧、活人碎嘴。完整规则与示例统一存于 `utils/dateStylePresets.ts`；入口与设置文风面板均显示完整文学风格名称（如「轻快幽默 · 日式轻小说吐槽 × 荒诞日常」），便于按文学偏好选择；不再在设置下方重复同一标题。前五套沿用原 ID 并替换为新版内容，不保留第二份旧版。正式互动只注入当前所选一套，开场只注入对应开场规则。示例省略出处，逐行使用现有表情标签，台词与叙述分行；多人物片段只示意写法，不授权代写用户。本场人称、角色自定义表情列表和语音规则仍由原管线决定。

基调分为随角色、松弛日常、心动推拉、直球偏爱；文风和基调不能替用户表态。场景种子是用户为本场指定的舞台，不倒写为共同往事。继续允许微小动作与安静延续，不强制制造事件；重生成继续轮沿用完整指令。文风仍只保存 `dateStyleConfig.style` 的 ID，新增五套沿用既有个人／全部用户备份与恢复路径，不新增存储字段或迁移。

开场观测与语音译文使用散文规则，前端分离后显示，原始回复完整保存。阅读模式相邻同情绪叙述缩小间距，不合并底层行或改变语音索引；立绘长行支持文本区内滚动，换行回到段首，点击跳过打字会停止旧定时器。开场、发送、重生成都在请求角色副本上准备记忆召回与门牌，不回写角色。

模型适配不按供应商名字添加刻板校准，也不自动关闭渠道安全设置。当前 DateApp 使用已有 /chat/completions 路径；实际模型拒答需结合响应与渠道证据定位，不能仅由文案推断原因。

## 场次与记录

- 靠近 TA：原感知开场，第三人称描写角色当下状态。
- 让 TA 靠近：沿用相同角色上下文与世界书，由角色根据既有地点、关系和约定合理靠近用户；不代写用户反应。
- 直接见面：不请求开场，进入会话后由用户展开输入框，输入发送或留空继续。

入口只决定开场方式，不强制续接旧话题或开启新剧情。退出立即离开，无确认框或保存提示。消息逐条落库，不再写入或恢复 `savedDateState` 播放快照。

每次选择角色生成独立 `dateEncounterId`，本场所有消息携带该 metadata；开场另带 `isOpening` 与 `dateOpeningMode`，重生成保留这些标记。异步回复捕获发起时的场次 ID，退出后返回的回复仍属于原场次，不更新新场次 UI。

阅读模式连续显示该角色的见面历史，包括旧场次和没有场次标记的旧记录。进入时读取最新 50 条，向上滚动或点击「加载更早」按消息 ID 游标再取 50 条；追加旧记录保留滚动位置，新回复不收起已经展开的历史。列表沿用原有正文、语音、SAR 与 OBSERVE 渲染，离屏正文延迟绘制。
立绘播放、失败重试与重掷仍仅操作当前场次，不因浏览旧记录而恢复旧播放快照。模型输入仍走完整的角色上下文管线，UI 的 50 条分页不限制模型上下文。
记录按次优先使用场次 ID，同场跨日不拆分，无开场或开场被删也不串场。旧数据继续按 `isOpening`，更早无锚点数据按日期兼容；按日期查看仍按设备当地日期归组。
