## 已确认的规则

- 后发 1 的四款图替换 `public/like520/parts/back1_01…04.png`，沿用原 ID、染色和形状参数。
  3D 外表面使用原贴图，内衬仍为平均色；不能再次把外表面的 RGB 全部涂平。
- 01–07 默认睁眼以 `public/like520/parts/eyes_01…07.png` 为配准基准，原款眉毛、高光、眼白、眼睑折线一起保留。虹膜染色不改变原图透明度和位置。
- 部件混搭时，**眼白以眼珠轮廓打底，再由当前上睫毛与眼珠下缘生成两侧填充区间**。
  新示意图 A/D 是睫毛两端，B/C 是眼珠下缘两侧：上边界沿睫毛，侧边以平滑曲线连接 A→B、D→C，下边界跟随眼珠。
  同款且未微调时使用配套原画眼白；只有混搭或调整上睫毛/眼珠后才重建眼白。
- **2026-09-29：暂时取消眼睛与睫毛的自动配准**。同款、混搭、睁眼、半睁都按各 PNG 的原始 472px 画布位置绘制；换睫毛、缩放睫毛不再自动移动眼珠，眼珠只叠加用户手动位移。眼珠与配套眼白共享用户位移；下睫毛使用自身原位置与独立微调。
  早期 A/B 对齐、+9 → +4、高度差补偿均已撤销。点击 01–07 可清除旧手动补偿恢复原款。
- **完整眼型与拆分眼珠使用同一个灰度染色函数 `faceTint.ts`**，复用旧捏人器 `applyEyesTint` 的 HSL 明度映射、底稿的黑色保护阈值 `preserveLineart`（默认 25）、10 级过渡和 235 白色保护阈值。颜色选择器对应中灰的目标颜色；源灰阶保留明暗关系，alpha 不变。先在原图空间染色，再缩放，取消原来的 65% 整层覆盖和两条不一致的分支。
- C/D 是眉毛外端 / 内端的笔画中心高度。自然状态保留原画；生气让内端略向下，难过略向上。
  原本已经朝该方向倾斜时只加 3°，其他情况加 6°；两侧镜像处理。开合状态的高度变化控制在 5 个原画像素以内。
- 半睁直接使用半睁原图坐标，取消之前的下缘补偿，便于用户比较拆分原画。
- 普通闭眼使用通用图；开心闭眼使用本款已画的版本。04 号始终是没有眼珠的眯眯眼。
  闭眼 / 开心闭眼隐藏眼睛、眼白、高光、自定义瞳孔和下睫毛。
- 嘴巴只有闭嘴、微笑、张嘴三个类别，不加半张嘴。嘴型独立于眼睛状态。
- **高光也保留自身原画坐标**，不再自动贴到睫毛下面或为半睁缩小。用户仍可独立调整大小、宽窄和上下；最终裁切到可见虹膜内，闭眼隐藏。细节层以 `source-atop` 合成，保留原透明边缘。
- 新增「原画 01–06」六款纯白高光，分别源自旧眼型 01/02/03/05/06/07；保留原画布位置，滤除眼白碎边。07 没有上方白色高光，仅把原图下方淡灰亮点转为白色，作为第六种可选款式；原款默认仍保留旧完整贴图。旧 PSD 的七款高光保留在「其他高光」，旧草稿 ID 继续有效。
  发布脚本 `art/chibi/publish-classic-highlights.mjs`，来源及 SHA-256 在 `faceHighlights.json`，所有非透明像素 RGB 均为纯白。

## 导入

```powershell
pnpm node art/chibi/import-face-psd.mjs D:/Downloads/6_0_29201.psd
```

专用发布脚本复用 ag-psd 和已安装的 sharp，包含隐藏图层中的所有款式。
**不适用普通 PSD 导入器“跳过隐藏图层”的规则**：此 PSD 用可见性切换备选素材。
导出 77 层：4 款后发、6 款下睫毛、6 款 × 2 状态 × 眼睛/眼白、7 款高光、
19 款上睫毛状态、4 款眉毛、1 张通用闭眼、12 张嘴型。
顶层散放的两张嘴是分组版的旧副本，不重复注册。

05 号已逐像素核对 PSD：睁眼来自「眼睛/05/正常」，半睁来自「眼睛/05/半睁」，导出正确，未与其他款互换。

## 保存与渲染

设置在 `HairSettings.face`，沿用衣橱草稿、保存和撤销。
无 `face` 设置的旧角色保留原合成五官；新建衣橱默认使用分层脸。
工坊在「确认形象，开始捏脸」启用；恢复旧草稿时保留已有款式。
`Puppet` 从 body identity 中排除 face 设置，通过 `setFaceSettings()` 原地更新面部纹理。
素材异步加载有版本保护，过期请求不能覆盖最新选择，销毁后的请求不能写回纹理。
`createVisitor()` 在进入小屋之前加载已保存的分层脸。

有分层表情时，身体动作不覆盖手选眼睛 / 嘴型。自然眨眼可单独开启；闭眼状态不再叠加眨眼。
旧脸仍保留原来的动作表情。这里采用独立控制与覆盖的思路，参考
[VRM expressions 的 blink / mouth 独立覆盖约定](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm-1.0/expressions.md)，
不引入新的模型格式或动画依赖。
遮罩复用标准 [Canvas 合成模式](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/globalCompositeOperation)。

## 工坊引导与微调

- 入口先确认已有 Chibi 形象，再选择体型 1（原版）或体型 2（可换装骨骼身体）。两者继续复用同一套头发与脸部贴图；体型选择随草稿保存，不再恢复时强制切到体型 2。
- SECTION 1 脸部：头发 / 眼睛 / 眉毛 / 嘴巴。眼睛内分眼型 01–07、上睫毛、眼珠、高光、下睫毛、瞳孔；一个页面只处理一类部件。眼型使用真实合成缩略图。
- 基础形象和发型选择复用现有 CreatorRollBridge；完成时只捕获当前编辑结果，不随机重抽形象。
- 每部件有大小、宽窄、上下；眼部整体额外有眼距，位于预览上方的可展开面板。`face.adjustments` 保存值；中性值为 100% / 100% / 0。调整眼珠上下时直接在原画坐标上叠加偏移。眼睛组的位移缩放同时作用于眼白与遮罩。
- `face.mouths` 分别保存 closed / open / smile。旧单一嘴型迁入所属类别，其余采用默认值。工坊正常状态保存闭嘴；嘴巴页面可分别试看三种用途，离开后恢复闭嘴。这是嘴型配置与预览，尚未接入语音驱动开合。
- 默认瞳孔保留在眼珠原画内，独立瞳孔滑杆作用于用户自定义瞳孔层。
- 然后进入 SECTION 2 衣橱、SECTION 3 体型细调；原版服装仍使用基础形象编辑器，3D 衣橱与骨骼比例调节用于体型 2。
- `/test/fixtures/chibi-face-controls.html`：独立内存交互验收，不写用户草稿。

## 原款 01–07 回归基准

`art/chibi/publish-original-eyes.mjs` 从之前发布的完整眼睛图中提取原款眉毛和高光（不移动像素，不修改原图），输出来源及哈希到 `faceOriginals.json`。07 原款无高光，不能再默认套用高光 01。

`applyEyePreset()` 恢复整套原款并清空眼部/眉毛的旧补偿、混搭和自定义覆盖，保留嘴型设置。主预览、眼型缩略图、基础形象接入均复用它。眉毛和高光菜单提供「原款」，仍可继续选其他部件。

验收增加七个旧图/还原图并排预览，比较全部 472×472 像素的 alpha，要求默认配准和轮廓完全一致；染色允许改变虹膜 RGB。仅检查 eyePairOffset=0 不足以证明默认组装忠于旧图。
