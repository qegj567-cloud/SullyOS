# 哔哔（原好友圈）

2026-10-22，已改为公共广场，并加入主动刷新、角色小号和抽取权重。完整玩法方案见 [好友圈与串门](../plans/home3d-social-visits.md)。

## 设置 App 的分类备份

纯文字备份保留动态正文、评论、文字配图、账号关系、设置及通知进度，剥除本地图片引用。`friend_feed_api`、`friend_feed_eval_v1_*`、`home_visits_v1`、`home_secrets_v1_*` 虽存于 assets，仍是文字记录：通过 `activityTextAssets` 单列分片导出，导入仅替换这组白名单记录。整合备份沿用完整 assets 和 Blob 旁路。

媒体备份通过 `friendFeedMedia` 按帖子 ID 保存上传配图，并保存可选的 `coverImages` 本地封面。导入只给仍存在的帖子补图、合并封面，不创建旧帖子、不覆盖正文、评论、账号关系、其他设置或 API；旧包没有封面字段时保留当前封面。素材表在媒体导入时合并，保留本机文字记录；旧媒体包内的整份 `friend_feed_v1` 也只恢复图片。微博登录会话保存在 sessionStorage，不随备份迁移，换设备需重新登录。验证见 `utils/activityBackup.test.ts`。

## 入口与共用页面

- 桌面／应用抽屉注册 `AppID.FriendFeed`（`friend_feed`），名称「好友圈」，懒加载 `apps/FriendFeedApp.tsx`。
- 家园小手机首页在信息、拍照之外增加好友圈；直接嵌入同一个页面，不跳走家园或切换当前角色。
- 独立 App 与家园手机读取同一个公共广场，不再建圈或分组。不同世界观的角色可以刷到彼此，未认识的人按陌生网友理解；小屋只固定外观，不隔离公开动态。
- 返回顺序为编辑／评论表单 → 好友圈列表 → 手机首页 → 收起手机。手机外框的返回首页与关闭按钮仍可直接退出。全局返回和手机内 Escape 遵守局部返回层级。

## 本轮可用功能

### 图文发布与首次引导

用户可发布文字、图文或纯图片动态，最多 9 张。支持 JPG、PNG、WebP、GIF、AVIF，单张原文件不超过 10 MiB，处理后合计不超过 24 MiB；静态图片复用 `processImageToBlob` 缩至最长边 1600，GIF 保留动画。草稿仅在内存中，取消后释放预览 URL；发布时存入现有 blob_assets，帖子 `images` 保存 blobref，不上传到微博或代理。完整备份复用 Blob 旁路；文字备份剥除图片引用后仍可导入正文和评论。

首页、六套主题、个人主页统计、图片页签、详情大图和分享卡片统一通过 `friendPostImages` 读取本地及真实配图。分享快照保存展示用本地图片；只有开启“分享时让角色看配图”才加入 `imageRefs`，沿原 ChatApp 识图管线发送。本地图片不经过微博图片代理。普通主/副 API 浏览仍为文字材料，明确配图数量并告知本轮未提供像素，不能猜图。

首次进入显示配置引导，检查参与角色的有效对话 API 地址/模型、抽取权重与情绪开关，不显示密钥、不发连通性请求。API 入口留在哔哔内，朋友/小号及互动入口进入对应设置子页；无角色时前往角色管理，微博入口直接扫码连接；说明立即评论/刷新产生用量、情绪浏览的 20% 概率、图片与真实阅读授权、记忆卡边界。每次打开引导先显示 10 秒倒计时，确认按钮禁用，到时只解锁、不自动确认；计时使用单调时钟并在卸载时清理。“知道了，开始逛”将 `setupSeen` 同事务存入哔哔数据，跨入口与备份保留；设置可以重新查看，不强制开启任何权限。

界面沿用 README 的动森约定，并为六套主题提供不同的信息结构。小手机固定「森间手记」；列表首屏五条，继续加载保留时间倒序。用户发帖、评论及确认删除沿原管线。

首次打开 App 在事务中迁移：`publicFeed=true`，唯一作用域 ID 为 `public`，包含当前仍存在的所有角色。旧圈的名称、背景和提示词留在 `archivedCircles` 作历史资料，不再注入；原帖子 ID、时间、正文、评论和记忆不变，受众变为公共可见。同步流与删除去重标记迁到公共作用域；首次同步状态保守合并，未初始化的流仍先静默拉历史。新建角色也可读历史公开帖子。

真实内容阅读授权只有旧圈全部开启且覆盖所有现有角色时才延续；否则合并后默认关闭，用户在全局设置重新选择。查看动态、合并圈子、切换主题不调用模型，不写角色记忆。独立私聊和记忆范围没有合并。

### 哔哔独立 API

引导「选择 API」和设置「哔哔 API 设置」打开 App 内的同一配置页。可从公共预设库选取，或手动填写地址、密钥和模型；选择只改草稿，保存才生效，取消不修改原配置。配置作为快照保存在 IndexedDB assets 的 `friend_feed_api`，与公开帖子/互动设置分开，不拼进素材或记忆卡。完整系统备份沿 assets 保存，分享角色卡不携带。

首页刷新、评论区刷新、用户评论后的即时接话都按 **哔哔独立 API → 当前角色 API → 全局 API** 整套选择地址/密钥/模型，遵守所选流式和温度设置，失败不切到其他配置。主回复顺带互动仍使用本次主请求的 API，情绪便车仍使用情绪 API，分享图片沿聊天识图配置；独立设置不改变这些请求的归属。引导中的可用角色统计使用同一优先级，只验证已填地址与模型，不宣称连通成功。

2026-10-22 正式 App 使用用户原有配置实测：首页刷新一次生成本人/路人共两条动态；用户评论一次请求得到另一角色接话。作者私聊实际显示本人发帖、用户评论收件、角色评论收件三张折叠卡；评论者自己的私聊显示评论行为卡。实际测试未额外修改主/情绪 API 或强制抽取概率，主/副 API 侧动作、水位线、分享图片及独立 API 路由由对应自动化测试覆盖，不能据此宣称所有外部模型均兼容。

首页顶部下拉松开或再次点击首页时，先逐个刷新已开启的微博主页绑定和关注流，每个来源读取最新一页；每页写入后立刻通知页面更新。某来源失败保留旧内容并继续其他来源。随后显示「朋友们正在赶来发动态…」，按权重抽一位角色，再抽内容类型：本人、身边路人 / 已加载世界书 NPC、无关陌生网友。默认角色等权 10，内容权重 60 / 30 / 10；每项范围 0–100，0 严格排除，全部关闭不回退抽取。关闭路人开关后，只保留本人类型。

一次刷新最多一次模型请求。使用抽中角色的 `resolveDialogueApi` 与 `buildFriendFeedReplyPayload`，复用 ChatApp 的 `loadCharacterContextRange` → `buildChatRequestPayload` / ContextBuilder、召回、世界书、实时上下文，只组装此角色的私聊。路人生成也由这一个请求承载，禁止读取其他角色的私聊。每轮随机目标为 2–5 条新动态：本人类型最多一条本人帖子，搭配启用的路人类型补充；相关路人 / 纯路人类型可生成最多五位 NPC 的帖子且本人 `kind=none`。关闭路人、角色禁止虚构联系人或只启用本人类型时，只生成本人一条。目标不是强制凑数，素材不足可少发或不发；落地校验总数不超过本轮目标。更大的 NPC 配额仅适用于首页刷新，评论与情绪浏览仍最多三位。刷新任务不可评论、转发或关注。缺少素材可不发。主动刷新不受本人自动发帖的五分钟冷却，但仍做正文去重；NPC 的冷却与防冒名保持。

`refreshLease` 在 IndexedDB 中跨入口互斥，十分钟后可重试；请求记录绑定此租约 ID，迟到响应不能写进新刷新。失败和结束释放租约；打开页面本身不刷新或产生 API 用量。刷新按当前设置生成，不建立后台轮询。

设置中每位角色有一个主号及最多三个小号。主号网名、标签与小号的名字、用途、标签保存在 `settings.identities[charId]`；用户网名单独存入 `settings.userNickname`。提示词列出仅本人的账号，模型用 `accountId` 自选发帖 / 评论 / 转发身份；省略为 `main`。落库校验只能使用该角色当前拥有的账号；名字与标签由程序取配置，不接受模型冒名。存储中的 `authorId` 始终为原角色，`accountId` 和发布时标签单独保存。主页按具体账号筛选，管理视角可以切换主号/小号；记忆仍按同一角色范围 / 水位线。移除小号保留已发帖与记忆。小号用途只提供给本人，不会注册或操作真实平台账号，也不是密码保护的匿名系统。

小号实际行为卡的上下文注明「使用账号…」，折叠卡只在展开后显示账号，仍保持轻量。NPC 帖不进任何人的记忆。全局提示词控制内容主题、语气与互动风格；不能改变权限、请求来源或动作限额。

「隐藏真实微博」是可逆显示开关，首页和个人主页隐藏直接同步 / 导入的原帖，保留本地动态和角色转发。不删数据、不关闭同步、不改变「允许角色阅读真实微博」授权；后者在设置里单独控制。

## 提示词与排版设置

右上角齿轮打开「好友圈设置」。全局互动提示词控制发帖与评论，可编辑或留空使用默认值，最多 3000 字，所有角色共用。下一次生成读取最新设置；角色人设、自主浏览的 20% 抽取、候选可见性、动作上限和输出契约保持不变。不改普通私聊的主提示词，也不为保存设置调用 API。

用户评论固定立即接话，不再提供主 API 搭便车选项；旧设置导入也归一为 immediate。评论保存后调用一次抽中角色的对话 API，可由角色本人或路人反馈，不保证帖主亲自回复。用户评论与作者收件卡先同事务保存；随后生成的本地反馈也进入帖主私聊收件卡。失败直接显示错误，不自动重试、不切换流式模式、不转交主 API；没有新回复时界面明确提示。每次评论会产生模型用量。
界面主题提供六套，独立于阅读密度：

- **动森信纸**：岛上来信顶栏、留言板封面、信封插画、奶油信纸与便签式评论。
- **微信朋友圈**：原创山景封面、左侧方头像、蓝色名字与灰色评论区。
- **Ins 风格**：独立 Instants 字标、圆头像、黑白界面，配图先于正文且整栏滑动轮播；纯文字独立版面，下方紧凑评论，不虚构点赞数。
- **蓝墨杂志**：SIDE B 刊头、钴蓝封面、逐篇编号、大字正文和细线分隔，评论如专栏批注。
- **微博风格**：独立的关注/我的顶栏、底部居中发布按钮、灰底白卡、头像下方时间与出处、九宫格、整行操作栏和卡片内评论。个人主页居中头像配分栏真实统计，长微博可展开全文。
- **推特风格**：独立的主页顶栏、头像旁发帖区、底部图标导航与蓝色悬浮发布按钮，名字/时间同行、连续信息流和带头像的串式回复。个人主页为横幅加重叠头像；图片页签只筛选已有配图。列表最多展示四张，余图数量叠在末张，大图仍可翻看全部图片。
这两套主题的外层底色、边界、主页、导航、设置和图片排版一起变化；各有独立界面组件，来源管理移到专门子页，首页优先展示动态；筛选、展开、发布、评论、原文和导航均连接真实功能，不伪造点赞/粉丝数，不新增真实平台写操作。

`settings.theme` 保存为 island / moments / insta / journal / weibo / twitter；独立入口首次使用、旧数据缺失或未知值时默认朋友圈，保留用户已经保存的主题，不改动态、圈子或提示词。头像支持真实角色和用户的图片、Blob 引用、emoji，缺图或加载失败使用名字首字；NPC 不冒用真实角色头像。样式全部限定在 `.friend-feed` 内，独立 App 使用保存的主题，家园手机始终渲染 island。

四套经典主题的页头用左右等宽区域保持标题居中，右上角进入「我的主页」，首页不再单列「首页／我的主页」页签。发布入口放在封面下方的「分享今天的新鲜事…」一行；点击标题从个人页返回首页，在首页再次点击才刷新。微博和推特保留各自的发布导航。

独立 App 已登记自理安全区，外层使用统一 `--chrome-top` / `--safe-bottom`，外壳不再重复加 padding。顶部跟随安全显示、紧凑显示、隐藏三种状态栏模式；iOS contain 的零安全区保持零，不补固定 44px。家园内嵌入口不再预留设备安全区。六主题和子页的返回点击区至少 44×44px，图标大小保持原样。`scripts/test-bibi-safe-area.mjs` 使用真实全局 CSS，模拟 0/44/62px 顶部安全区与三种状态栏模式，检查主页面、设置子页及内嵌入口。

朋友圈首页和六主题个人主页的封面区域可直接点击更换，不显示常驻编辑按钮；头像保持独立的主页入口。封面编辑页选择本地图片、预览、保存或恢复默认，取消／返回不修改旧图，保存后逐级返回原页面。图片复用 Blob 存储，`settings.coverImages[ownerId]` 仅保存 blobref；同一角色的小号共用人物封面。支持 JPG、PNG、WebP、GIF、AVIF，原文件不超过 10 MiB，复用 1600px 图片处理。完整与媒体备份携带封面像素，纯文字备份剥除；恢复普通偏好保留封面，封面页单独恢复默认。

动态排版提供「舒展 / 时间线 / 紧凑」，正文字号提供 14 / 16 / 18 三档；可收起首页封面。设置页用六个缩略样例选择主题，真实动态样式实时预览草稿，取消和返回都不保存；「恢复默认设置」也先改草稿，点击保存才生效。

家园小手机固定「森间手记」信纸与奶油色机壳，不展示主题选择；小手机保存其他设置或恢复默认时保留独立 App 的已选主题。阅读密度、字号与互动规则仍共享。

设计参考 README 的动森约定与 [Anthropic frontend-design skill](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md) 的字体层级、内容驱动构图和视觉自查建议。微信与 Ins 主题借鉴信息结构，保留「好友圈」名称，不使用平台商标；没有新增远程字体、图片或运行时依赖。

全局设置、权重与账号保存在同一份 `friend_feed_v1.settings`。旧圈补充仅保留在迁移档案中。旧数据无字段时沿用默认外观，不迁移正文；并发保存读取最新状态，不覆盖新评论。两个入口共享设置，完整备份和文字备份都随原好友圈数据携带。

列表、主题栏目导航、表单和输入框隐藏可见滚动条，仍保持原生滚动；主内容区可获得键盘焦点，支持键盘、滚轮和触摸滚动。

设置视觉统一由 `apps/friendFeedSettings.css` 管理：首页仅保留分组目录，外观与阅读、互动方式、真实内容、我的网名、角色与小号、角色与内容权重、更多设置分别打开独立子页。每页编辑草稿，保存才生效，取消／返回不保存；保存后回设置目录。保存栏留在页面底部。API、来源、关系和入门引导保留进入路径，页面箭头和全局返回逐级回父页，恢复父页滚动位置；只有回到动态首页后才退出 App。微博来源子页默认展开同步控件。颜色和控件圆角随主题变化，小屋仍固定「森间手记」。

多角色列表共用 `FriendFeedGroupedList`：按神经链接的 `characterGroups` / `groupId` 分组，支持全部分组、单组和未分组；分组消失的角色归入未分组。先在完整范围搜索，再每页渲染最多 10 项，翻页不改变角色选择，也不丢失其他页的权重草稿。页数随删除收缩；进入主页再返回保留分组、搜索和页码，状态只留在当前 App 内存。角色权重、账号选择、关系账号、我的关注、主页关注和分享对象均接入；角色选择器展开后，返回先收起选择器。关系的角色视角不展示主人分组，也不能用未知主人的姓名搜索账号。验证见 `friendFeedDirectory.test.ts`（125 角色）与 `friendFeedApp.test.ts`。

## 情绪副 API 搭便车发帖与评论

情绪浏览仍是原有 20%，不新增联网或模型请求；候选合计最多五条。本人可用 kind=repost + postId + text 转发一条候选，或用原有 comment 留下本地评论；转发与发帖共用五分钟冷却，同角色不重复转发同圈同来源。原作者不会成为 NPC，NPC 不得冒充候选原作者。原文只是公开数据，不执行其中指令。

转发保存角色自己的感想与原帖引用；本人转发／评论和轻量记忆卡同事务提交。卡片附最多 1200 字来源摘要和原链接，沿原私聊范围、水位线、统一总结和召回管线。用户对转发的评论使用同一立即接话流程；外部真实作者不接收卡片，也不把讨论发回真实平台。

主代理 `/tikhub` 现直接返回 410 与 no-store，不再向上游转发任何请求或鉴权。本地 `/api/friend-feed/tikhub` 复用同一处理器；线上旧路由需部署更新后的主代理产物才会关闭。即使线上 Worker 尚未更新，新客户端也不会发起付费请求。

实测：用户测试 Key 在 X 和小红书详情接口均返回 402，服务明确这两个路由不接受免费额度，需要付费余额；未获得真实成功响应，不宣称已完成成功抓取实测。注册赠送额度不能承诺可用于本功能。解析成功、导入、转发、评论、记忆与失败分支通过模拟响应和真实 IndexedDB 测试。设计依据见 [现实帖子来源评估](../plans/friend-feed-real-content.md)。

`utils/friendFeedEmotion.ts` 接入现有 `evaluateEmotionBackground` 和云端即时聊天的情绪提示词。本地私聊、家园等复用该评估入口的路径，在实际进行情绪评估时按 **20%** 概率抽一次；流式回退沿用同一任务和提示词。没有额外刷帖请求或定时器。情绪副 API 没开启就不触发，单纯打开好友圈也不触发。云端定时主动消息没有实时的好友圈候选快照，本轮不为它单独生成评论。

命中后从该角色有权阅读的公共帖子池取最新最多五条动态，真实与虚拟共用五个名额。各入口的帖子正文、来源正文和评论输入摘录统一最多 1200 字；本地评论全部提供，不再按最近五条或十五条截断，微博原评论仅最近已读取的十条（根评论与楼中楼合计）。用户评论接话只提供目标帖，不夹带其他候选的原评论。未获取真实评论时不编造材料或引用 ID。明确分享仍保留完整快照，不受普通浏览摘录限制。尚有未过期用户评论待办的帖子暂不进入副 API 浏览，避免与即时请求抢同一个互动；用户待办不由副 API 领取或消费。人设、世界书、记忆沿用本轮已有主上下文，不二次装载世界书。空广场也可发第一条日常。

输出为原情绪 JSON 的可选字段 `friendFeedAction: {requestId, kind, text?, postId?, comment?, accountId?, npcActions?}`。`kind` 为 post/comment/none；保留旧 `{requestId, postId, comment}` 兼容。本人每次最多发一条动态（4000 字）或评论一条（2000 字），可以不行动。自动本人发帖至少间隔五分钟，同正文不重复发布。`changed=false` 也处理；坏字段或截断结果不发布，也不影响正常 buff。角色刚评论过、还没人接话时，不连续自言自语。

`npcActions` 在情绪浏览和评论时最多六项；提示词鼓励有话题时写 3–6 位不同网友的短评（允许纯表情、1–8 字短评，也允许偶尔 100–500 字的具体讨论），接梗、吐槽、追问或争论，可以少写或不写。副 API 中路人新帖仍最多三条；首页刷新独立维持 2–5 条动态目标。主 API 动态通知也可附带最多六位路人评论，不生成路人新帖。均共用本次请求，不追加模型调用，真实角色仍最多一个自身动作。格式 `{kind: post|comment, name, text, postId?, replyToCommentId?}`。优先使用已加载世界书的 NPC，缺少合适人物时可创造符合公开背景的路人；不是凭名字查找或挂载其他角色的世界书。程序为名字在本圈生成稳定 `npc:<circleId>:<normalizedName>` ID，不接受模型指定真实角色 ID；真实角色和用户名字不可冒充。每位 NPC 每轮最多一个动作，同一 NPC 发帖有五分钟间隔与正文去重。NPC 不产生角色记忆卡，既往帖子仍留在好友圈可读素材中。提示词要求 NPC 不知道私聊、内心、未公开记忆和其他角色的私人内容；人物设定一致性由模型遵循，不声称程序能理解并验证所有世界书事实。

生成前在 `assets/friend_feed_eval_v1_<charId>` 保存候选请求；同一候选五分钟内的并发评估不重复预约，最多保留二十个请求，二十四小时后失效。本地失败/取消/无评论释放预约；云端迟到结果仍需命中真实预约。落地再次检查真实角色、原候选、当前公共作用域与真实来源授权、帖子是否存在、是否已评论；消费请求与写入评论在同一事务，重投不重复发。

**记忆卡与公开行为同事务提交**：真实角色的动态写自己的完整正文卡；真实角色的评论写自己的短评卡（原帖摘要最多 1200 字，若为接用户评论，附上该触发评论）；自己的动态收到他人评论时写「收到评论」卡，同一生成批次的多个 NPC 回复合并为一条。用户评论与作者收件卡同事务写入，只通知仍可见该帖的真实作者。路人帖子不发卡，也不广播给没读帖的角色。卡片均为 `role=system / type=friend_feed_card`，私聊以窄小的两行记录显示，点开才看详情；无大图、头像或大标题。

下一次主请求读取角色时间线时自然包含这条记录；已经发出的并行主请求不会中途被改写。卡片跟随该角色原有范围、水位线和统一记忆总结，不添加常驻高优先级提示，不另建记忆库，不为单条评论立刻加一次总结 API。写入事件刷新私聊并标记云端上下文需同步。删除原帖不抹掉已经发生的自身经历；用户仍可通过原有消息管理删除卡片。

## 用户评论后的即时接话

评论落库时按联系人 / 共同话题优先池和角色权重抽一位承载角色；本人有 80% 的参与机会，禁 NPC 时允许本人回应。开启路人且承载角色允许虚构联系人时，另有随机 3–6 个 NPC 名额，实际可以更少或不生成。NPC 原作者可在路人部分接话；生成评论不递归触发请求。帖主不必就是执行角色，帖主的收件卡仍保留用户评论及后续本地反馈。

UI 在保存这条评论后直接调用一次 LLM，并显示接话中 / 结果 / 错误。请求绑定本次 triggerId，不能在新评论时顺带清空旧任务。replyJobs 只用于记录当前尝试、校验与跨窗口防重，主 API 不领取。失败即结束该尝试并报错，不自动重试、不从流式改为非流式、不改派角色。尚未取得预约的第二窗口不得结束第一窗口的任务。旧搭便车任务（没有 delivery=immediate）直接退休，不额外花费；页面被关闭中断的即时尝试在触发评论发布 24 小时后释放，迟到结果仍校验时间与预约。

立即评论与刷新复用 buildFriendFeedReplyPayload：loadCharacterContextRange → buildChatRequestPayload，内部统一执行记忆召回、ChatPrompts / ContextBuilder、世界书和实时上下文装配。只带抽中角色自己的历史与水位线，NPC 共用此请求，不读取其他角色私聊。公开材料只是任务数据；提示词要求不泄露私聊或未公开记忆。

### 分享到角色私聊

帖子详情的「分享给角色」进入选人页，默认不选，明确发送后才写一张 `role=user / friend_feed_share_card`。不自动请求主模型、不启用真实内容自动浏览。显式分享授权所选角色读取这次公开快照，不要求先打开自动浏览权限。同步读取原评论失败保留缓存并提示；没有连接时使用已缓存评论。

分享内容是发送时的快照：帖子完整已存正文、原来源正文（原平台仅给摘录时明确标注）、最近 10 条微博原评论、**全部**本地用户/角色/NPC 评论及引用。晚来的评论不改旧卡片，重新分享得到新快照。发送动作有防重 ID；角色删除、帖子删除、来源停用、图片开关或代理变化后拒绝旧请求。普通消息范围、独立水位、世界书和记忆管线仍生效；记忆语义是“用户分享了这条帖子”，不能把原评论记成角色自己的发言。

「分享时让角色看配图」默认关闭，仅影响后续分享。打开后通过当前代理的无登录凭据图片读取接口，将可用配图存为本地 blobref 附件（每张最多 6 MiB、总计 24 MiB、最多 18 张、并发 3）；失败会提示实际附带数量，正文分享仍可用。主历史按标准 `image_url` 发送，网络出口还原本地引用；开启独立识图 API 时使用既有识图函数并缓存多图描述，不把凭据交给模型。用户须配置支持图片的主模型或识图 API。不支持图片时可关闭开关。旧分享保留当时的图片选择，正文/记忆正规化不拼接媒体二进制。

分享卡原生无描边、阴影或底色，外层复用 `ChatCardSurface` 的全局美化；摘要只用于展示，展开查看分享快照的原文与评论。预览 `test/fixtures/friend-feed-share.html` 对比原生与全局白框，仅合成数据、不写 DB、不调用 AI。

## 用户收到回复：全局提醒与站内收件箱

`utils/friendFeedInbox.ts` 管理 `friend_feed_v1.userInbox`，与提供给角色的 `notices` 动态提示队列分开。所有生成入口（主/副 API 搭便车、即时接话、评论刷新）共用落库事务：别人评论 authorId=user 的帖子，或明确回复该用户的本地评论时，保存一条用户提醒。用户自己发言、路人之间普通讨论、同步来的微博原评论都不产生用户提醒；旧评论不补发历史提醒。绑定到用户的真实主页帖子也按相同规则处理。

本地评论素材带 id 与 authorId。接具体评论必须输出 `replyToCommentId`，引用同帖本轮候选中的评论；保存前复核 ID、作者和正文未变化，拒绝编造、跨帖、过期引用。即时接话未指定引用时自动关联本次用户触发评论；明确回复微博原评论时不自动关联用户。保存后的 `localReply` 用于评论区、分享快照及角色自身行为卡展示。两种引用和所有操作均仅在本地，不回传微博。

全局提醒由 PhoneShell 挂载，用户在其他 App 或桌面也能看见；同一结果的一批回复合并为一条横幅，点击跳对应帖子，多帖则跳收件箱。横幅 8 秒后收起，也可手动收起，均不清未读。`announced` 用 IndexedDB 事务领取，避免重复结果、多标签页重复弹；锁屏或隐藏页面不领取，恢复可见后再处理。这是糯米机内全局横幅，不新增系统推送或后台生成。

六套主题与家园入口共用小铃铛、未读数及收件列表。仅打开列表不清未读；进入可见的目标详情，仅将当前展开显示的评论所对应提醒标记已读（折叠内保留未读），也可按当前快照点全部已读。删除帖子同时清理其提醒。未读不因数量丢失，新增提醒时仅保留最近 200 条已读历史。隐藏或停用的真实来源遵守现有可见性规则。通知、评论、记忆卡同事务提交，失败不制造空提醒；通知本身不调用 API，也不额外写角色记忆卡。

验收：`friendFeedInbox.test.ts` 覆盖六位 NPC、主 API 文本动作、即时引用、用户目标识别、无效引用、防重、并发领取、已读与删除；`friendFeedApp.test.ts` 覆盖六主题入口、详情已读与返回、全局合并提醒及跨 App 跳转。

## 路人口吻与楼中楼（2026-10-22）

设置新增独立的 npcPrompt「路人提示词」，默认 DEFAULT_FRIEND_NPC_PROMPT；旧备份自动使用新默认，留空也使用默认。用户可以展开修改，保存后作用于下一次生成；真实角色仍遵守自己的人设。主 API 动态通知、副 API 浏览、即时接话和手动刷新都读取同一份路人风格。默认要求口吻、长短、理解程度与立场参差，不把路人写成统一捧场团或角色分身，不机械集齐类型；允许表情、问号、困惑、插科打诨、不同意见与具体专业讨论。当前 NPC 与角色评论上限统一为 2000 字、帖子为 4000 字（2026-10-31 调整），不增加调用次数。

每条本地评论提供「回复」，微博原评论提供「在本地回复」。编辑页展示明确对象与原话，取消不写记录、不请求 API。保存时只接受当前帖仍存在的目标 ID，错误不降为顶层评论；保存后沿即时接话管线只调用一次 API。用户点名真实角色且该角色可阅读、权重大于零、无相关关系禁用时，优先由该角色的上下文接话；否则沿既有池抽取，其他角色不能冒充对方。被点名角色在别人帖子下收到用户/生成回复，也会有「自己的评论收到回复」轻卡；帖主收件卡与用户未读通知继续共用原事务。

存储与模型输入仍是平铺的全部评论，通过 localReply.id 保存父评论。UI 用 friendCommentThreads 把多层来回归入同一根评论下一层缩进，每条仍能继续回复；不无限缩窄屏幕。缺失父项或导入循环不丢评论。旧记录没有明确引用时保持原样，不靠文本猜测父项。

同一次生成也支持 NPC 互相接话：npcActions 中的评论可用 replyToNpcIndex（零起始序号）引用本数组前面、同一帖的 NPC 评论；仅允许向前引用，禁止自己、未来项、跨帖、非评论项。它和 replyToCommentId / replyToSourceCommentId 互斥。程序按序生成真实 ID 并写成普通 localReply；不额外调用 LLM。每人仍最多一个动作。原站引用只保存本地快照，不往微博发回任何内容。

测试：friendFeedThreads.test.ts 覆盖多层/孤立/循环、具体角色上下文与收件卡、原评论本地回复、纯表情与长评、同批互回及非法引用、旧设置与独立提示词；六主题 UI 测试覆盖指定评论、取消、提交后回到楼中楼、设置草稿保存。

实际验收：正式 App 的已有验收帖中，点击一条 NPC 评论后发布用户回复，收到真实 API 的角色与路人回复；页面将用户、原 NPC 及其他接话归到同一楼，并可继续回复楼内任意一条。原有无引用的旧评论不会被猜测归并。

随后继续回复该楼里的 NPC，第二轮真实 API 生成三条路人回复，分别为较长解释、生活吐槽与短评；全部仍归入原根评论。两轮使用原有配置，没有修改用户模型、Key 或微博代理，也没有增加额外生成管线。截图：tmp/bibi-thread-live-verified.png。

### 楼中楼折叠与提醒定位

每个根评论默认只展示前三条楼内回复，超过三条显示「查看全部 N 条回复」，展开后可收起。折叠只影响界面，存储、角色上下文与分享仍读取全部评论。站内每条提醒携带 postId + commentId，全局同帖合并横幅携带本批最新回复的 commentId，多帖横幅先打开收件箱。进入详情后自动展开目标所在楼，滚到目标评论并给予轻底色、焦点；已在详情中再次点同一提醒也会重新定位，不因后续数据刷新反复抢滚动。不可见/已删除目标不会猜测定位到别的评论。

读取提醒只确认当前展开显示的评论，折叠内的回复仍未读；展开后再确认。六主题与小屋共用此行为，不调用生成 API。friendFeedApp.test.ts 覆盖前三条、展开/收起、折叠未读、站内与全局精确目标、重复定位和零 API 导航。

### 禁止生成内容冒充用户（2026-10-22）

用户确认：禁止的是冒充用户发帖/评论，正常提及姓名、引用用户已有原话允许。所有生成入口共用 `landFriendFeedEmotionAction`：提示词明确禁止代用户发言；代码只允许当前角色自己的 accountId 或合法 NPC 名称，拒绝模型附加 authorName / ownerId / charId / role 等作者覆盖字段。follow/unfollow 的 authorId 是关注目标，可以指向 user；评论的 replyToCommentId 也允许指向用户评论。引用快照仍由程序从已存在的评论生成，不接受模型伪造作者或引用。

提交事务同时读取最新 user_profile，保护当前姓名、本次请求时姓名、历史用户发帖/评论昵称及绑定到用户的已同步微博原作者名称。身份比较统一 NFKC、大小写、空白与不可见格式字符、开头 @；同名角色主号、小号和 NPC 均拒绝发布。拦截整批生成内容，不先发布合法部分，也不写记忆卡或提醒。旧 NPC 稳定 ID 保持不变。此比较只用于作者身份，绝不扫描正文禁词；自由正文中语义上的冒充仍需要模型遵守提示词，不能宣称程序能识别所有变相冒充。既有真实用户输入与原站只读同步不受生成拦截影响。

### 账户级关系网（2026-10-26 已接入）

入口：哔哔设置中的账号编辑与「关注与身份关系」，也可从「我的关注」进入关系管理。采用可搜索的账号列表，每行分别编辑「关注这个号」「知道是谁」；选择人物、发起关注的账号，并切换「以 TA 视角查看」。关系修改立即保存；进入关系页再返回时保留外层尚未保存的设置草稿。恢复排版默认值保留网名和小号。

`utils/friendFeedGraph.ts` 管理 `friend_feed_v1.accountGraph`，沿用资产备份，不另开数据库：

- `accounts` 保存不包含主人信息的稳定公开 ID 与内部 `ownerId / accountId` 映射。改名不改变关系。人物仍承接人设、私聊与记忆；用户一个主号，角色主号 + 最多三个小号。
- `follows[sourcePublicId]` 是目标账号 ID 数组，按账号有向保存。同一人物不同账号可分别关注不同对象；通知检查具体发布账号，不能由一个小号的关注扩散到主人所有账号。
- `known[viewerCharacterId][targetPublicId]` 保存身份认知布尔值。同一角色自己的账号共用认知。账号双方互关时认出参与互关的两个账号，不顺带认出其他小号或告诉旁观者。显式 `false` 优先于互关自动认知；取消关注不清除认知。
- 查手机联系人、共同话题、真实微博关注均不自动揭晓小号身份。本人明确掉马或用户明确告知时，可由当前生成请求提交带证据的身份认知，验证通过后只更新观察者。手动取消认知只影响后续哔哔材料，不抹除私聊、世界书和历史总结已经提供的事实。

例：A 关注 B 的咖啡号、吐槽号，只知道咖啡号背后是 B。A 刷到吐槽号时仍按陌生账号互动；第三个摄影号未公开、未关注、未认出时不出现在 A 的预览列表。管理视角展示真实归属，角色预览只显示公开网名和已知身份，且不能借主人的头像、分组、搜索或主页跳转查看隐藏归属。

主/副 API、刷新与即时评论共用按观察者投影的帖子/评论材料：未知作者改为不包含主人信息的账号 ID；已知时附加 `identity`。本地引用、分享卡快照和收到互动的记忆描述同样处理；账号私有用途只给本人。关注操作格式中的目标是公开账号 ID，自己的 `accountId` 决定用哪个号关注。发起请求时记录关系和账号配置签名，响应到达时关系已变则拒绝落库，避免沿用过期认知。

后台依旧用内部人物 ID 路由记忆，小号发帖、评论、转发写本人私聊卡及原有水位。分享同一帖子给不同角色会生成各自的身份快照，不在卡片元数据里偷带未知主人。禁止冒充用户的多层校验继续生效，新增用户网名与历史用户昵称保护；正文正常提及、引用用户不受禁词拦截。

评论抽取按人物去重：结合可识别的熟人关系、发帖账号话题、关注和用户权重选择承载角色。三个小号不会得到三次抽签机会。真实微博绑定仍映射对应人物的主号，并使用哔哔网名；不自动发布到小号，不因改名重复同步或产生记忆卡。

旧 owner 级关注只迁移到主号，用户默认关注角色主号，新增小号不自动关注。退役小号保留历史帖子、映射与记忆，移除它的关注边；备份还原保留稳定 ID、关注和认知。主页按具体账号筛选，管理视角提供账号切换；真实微博关注列表仍独立展示。

验证：`friendFeedGraph.test.ts` 覆盖迁移/备份、并发关系编辑、局部互关、手动认知、身份投影、分享及记忆、精确通知/关注、退役账号和反冒充；App 测试覆盖实际设置保存、草稿返回、角色视角只读与账号主页；微博测试覆盖网名同步。`test/fixtures/bibi-relations.html` 是只使用内存示例、不访问真实备份或 API 的交互预览。

### 角色文字配图卡

角色与 NPC 的新帖、角色转发动作可选 `imageCards: [{caption, description}]`：每帖最多三张，标题最多 40 字、画面描述最多 600 字；有配图时允许 `text=""`。普通文本 API 同轮输出，不增加绘图、上传或识图调用。评论暂不支持此附件。提示词要求只描述可公开的虚构画面，不冒充用户，不编造用户照片，不泄露私聊，也不强制每帖配图。

六套主题、帖子详情和私聊分享共用照片便笺式卡片，点击展开完整描述；纯文字配图也计入图片筛选与主页媒体数量。文字配图不进入真实图片 URL、下载或 vision 管线。浏览材料与分享上下文明确标注「作者描述的画面，无真实图片像素」；即使关闭真实图片识图，描述仍是可读文字。角色自己的发布记忆卡、评论引用和收到互动的帖子摘要带上画面描述，路人帖不写成角色自己的行为。快照和备份保留这些卡片；内容变化会使旧请求失效。

校验拒绝超限、空描述和 URL 等额外字段，不自动截断落库。`friendFeedImageCards.test.ts` 覆盖生成/记忆、分享/备份、NPC、非法数据和竞态；App 测试覆盖六主题、展开不跳转、详情和图片筛选。`test/fixtures/bibi-image-cards.html` 提供不访问用户数据或 API 的主题预览。

配图外观随六主题采用不同构图：森间手记是纸签与圆角章；朋友圈是紧凑方块；照片墙是黑底文字海报；杂志是大编号与错位标题；微博是暖灰图文块与底部说明条；推特是细描边媒体卡。统一使用原生 details 展开/收起，长描述不截断，窄屏标题缩小；私聊分享不继承某一主题，保持中性。预览支持六款对照、三张配图与长文本。

### 明确掉马与用户告知：自动保存认知

`utils/friendFeedRecognition.ts` 给现有 `friendFeedAction` 增加可选 `learnIdentities`，每轮最多三项 `{accountId, personName, evidenceId, quote}`。`accountId` 是公开账号 ID；本人正常发布时选择的外层 `accountId` 仍是自己的主号/小号 ID，两者不混用。`kind=none` 也能保存认识，无需公开发言、关注或额外 API。

- 刷帖子：主/副 API、即时评论和刷新沿已有调用处理，仅本轮选中的帖子和本地评论可作证据。原站评论、旁人猜测不能替账号本人确认身份。
- 用户告诉角色：ChatApp 传入已选上下文中的最后一条用户文字；家园传入本轮用户本人说的话。即使没有动态通知、未命中副 API 的 20%，主回复也可处理。不会额外翻读 DB 的旧私聊。用户提到已经认得的网名时，直接补充这个账号的已有认知，避免原记忆卡归档后又认不出。
- 分享帖子：已选上下文中最近一张用户分享卡也可提供证据，即使没有开启环境浏览。按分享快照匹配原帖和当时的本地评论，不偷偷加入分享之后的新评论；原帖/评论已经改动则不使用旧快照确认身份。分享本身不冒充用户的身份声明。

提示词要求引用明确肯定的确认语句，不能按口气、职业或相似网名猜；疑问、否认、玩笑、角色扮演、引用和传闻不算确认。程序核对本轮证据 ID、逐字引用、作者、当前内容和真实账号归属；人物姓名或已经认得的账号名必须无歧义。不会把待确认的主人映射提前给模型。常见猜测/否定格式会被拒绝，但自然语言是否确在自报身份仍依赖模型判断，不宣称识别一切玩笑或间接表达。建议用户明确说「半夜吃面是顾夏的小号」，指代不清时不猜。

认知与 `kind=identity` 的轻量哔哔记忆卡在同一事务写入；卡片标题「认出了一个账号」，展开查看确认原话。仍归这个角色的正常私聊记忆与水位线，不写到别的角色，也不生成公共评论或提醒。关系页自动显示认出状态。`accountGraph.learned` 保存已用证据 ID 与原话，随完整备份保存；同一证据不重复写卡。手动取消认知后，不会因重读旧证据立刻认回；后来出现新的明确说明可以重新认出。请求途中关系变化仍拒绝旧响应。

测试：`friendFeedRecognition.test.ts` 覆盖本人掉马、无通知的用户告知、已知身份回忆、评论与分享快照、熟悉网名指认、局部认知/记忆、错误归属/伪造引用/猜测、非本人发言、手动修正、重复响应和请求竞态。

## 评论管理与生成容错（2026-10-31）

动态详情里的每条本地评论均提供「编辑」「删除」，包含用户、角色和 NPC；微博原评论仍是只读来源。编辑原位保存并标记已编辑，已有回复的引用同步更新。删除仅移除选中的评论，其余回复保留，移除对已删文字的引用和对应收件提醒。已有私聊记忆卡保留为历史记录，编辑与删除本身不请求模型、不生成新记忆卡。

修改在读取最新数据的同一事务中完成，按打开编辑页时的原文检查并发覆盖；编辑或删除会增加讨论版本，拒收根据旧讨论快照生成的评论，并取消被修改评论触发的待办。角色换身份、任务失效、越界回复和防冒名校验继续生效。

正文上限统一由 `utils/friendFeedLimits.ts` 维护：动态 4000、评论 2000（与 textarea 一致，按 UTF-16 长度计数）。原角色动态 800 / 评论 180、路人评论 500 的限制取消。独立首页刷新输出额度 16000 tokens，评论刷新与即时接话 8000 tokens；不额外调用或自动重试 API，服务自身的模型额度仍适用。

专用生成入口允许完整的裸动作对象、代码围栏、kind 大小写和空白、等价的 text/comment/content 写法，以及 request_id/account_id/post_id；有冲突的 ID 不接受。缺失或错误的 requestId 不猜测，截断的动作不补全后发布。任务示例只给本轮允许的动作，主要拒绝原因区分正文/格式、身份、数量、重复及过期，不再全部折叠为同一句泛化提示。
