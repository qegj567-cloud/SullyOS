# 房间布局分享

入口：正式小屋的「房间」或「装扮」→「分享当前房间」。下载 `.room.json` 或复制 JSON 参数；接收者在相同入口粘贴或选择文件，读取摘要后点击「应用到当前房间（可撤销）」。原有整屋导出/导入现明确命名为「导出整屋备份 / 恢复整屋备份」。文件不包含模型，接收端需要支持相同家具素材的版本。

## 数据范围

`roomSharing.js` 的版本化格式为 `format: sully-room-layout`、`version: 1`，携带 `roomSizeVersion` 和单个 `room`。白名单包含房名、墙/地/边框色与样式、边界门洞、已摆家具的素材 ID、位置、朝向、主体/局部颜色、长度、承托与桌椅吸附关系。坐标归一到单房间，实例 ID 改写为 `item-N`。不包含角色、聊天、其他房间、收纳物品或来源实例 ID；不上传到服务器。

导入重新生成家具实例 ID 并重连 supportId/dockId，先校验文件格式、尺寸版本、素材、坐标、承托和碰撞，再在副本上准备结果。最大 1 MB / 100 件，仍受手机容量规则限制。失败不修改房屋，不自动丢弃未知家具。当前房间已摆家具被替换，收纳箱与其他房间保留；邻房共用墙优先保留，如无法还原则拒绝应用。跨房间组合或越出单房间的布局不适合此格式，应使用整屋备份。

最终应用走编辑器已有 commit/persist/undo/redo；导入前仅展示摘要，用户点应用才修改。输入框禁用场景快捷键，避免输入参数时触发全屏或移动家具。

验证：`utils/room3dSharing.test.ts` 覆盖白名单、存档隔离、链接/ID 重建、收纳保留、版本与缺失素材等非法输入；浏览器验收覆盖真实下载、剪贴板、粘贴/文件读取、应用和撤销。
