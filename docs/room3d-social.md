# 多人家园与串门

2026-10-26。入口：拜访（测试版）3D → 我的家 → 邀请与串门。公共哔哔继续独立运行，家园不要求先分生活圈。

## 一起生活

房主之外最多三个位置，用户形象也占一个位置。手动邀请名单保存在该家园，重进恢复；预约访客只临时占位。形象必须先在手办柜保存。离场会释放动作和座位。

访客各自计时，自主走动、观察、坐下与起身，不调用 API；避免抢占房主、其他访客的座位和行走目标。只在当前可见房间活动，不偷偷跨房间继续共享事件。家具不可达时不制造已完成记录。房主保留原来的完整家具活动；访客目前并未开放房主的所有家具专属动作。

用户控制小人走动时优先绕开其他人；门口或狭窄通道没有绕行路线时，允许沿有效地面路线临时穿过其他小人，避免召唤房主后双方互堵。行走中有人进入路线也会重新寻路。墙体、家具和地板边界仍按原导航检查，落脚终点必须与其他人保持距离，不推动或瞬移旁人；临时通行标记只属于本次行走，不写存档。座位占用及双人动作空间检查保持原规则。

熟人互动读取查手机通讯录的 `kind: real` + `linkedCharId`，保留双方各自的认识状态和好感。名字相同、虚构 NPC 都不会自动映射；任一方拉黑禁止自动接近和串门。关系影响本地动作选择，不在提示词中泄露对方的私有好感数值。当前熟人自动互动使用已存在的交谈动作。

## 浪漫关系硬限制

「我的家 → 邀请与串门 → 浪漫关系」按当前家园的具体角色 ID 对确认关系；用户也以 `user` 作为独立成员。默认全部关闭，旧存档不自动开启。高好感、共同居住、关注关系、角色昵称和模型正文都不授予权限；A–B 的确认不会授权 A–C 或 B–C。

当前所有「亲密」分类动作以及拉手转圈、揉肩需要确认关系；包括拥抱、公主抱及其被动方向、牵手等。模型动作列表、互动轮盘、拍照动作列表统一过滤；实际执行入口再次检查。动作文件异步加载完成后再次检查；撤销关系会取消正在准备或执行的双人动作和拍照摆姿势。普通聊天、递水、击掌等不受此限制。

提示词只提供当前说话者与在场成员的已确认浪漫关系，并禁止用文字冒充已完成的亲密行为。程序能保证未授权的 3D 动作不执行；自由文本是否始终遵循提示词仍受模型影响，不能把提示词约束说成任意模型文字输出的绝对保证。关系设置只在当前家园生效，不自动改写查手机备注或哔哔关系。

## 公主抱动作（2026-10-29）

「公主抱 / 被公主抱」已接入两段真实 Meshy Prime 动作，保留躯干与头部变化，并由 `chibi/princessCarry.ts` 校正双人托背、托膝、收腿、升降与落地。接触手臂使用固定肘部方向和柔和伸展限制，先落脚再松手；身高差、倒向发起、取消复位共用正式运行器。只支持二号素体，浪漫关系权限不变。来源、成本及复查步骤见 [公主抱制作记录](../art/chibi/princess-carry-2026/README.md)。

## 多人 API 与记忆

用户发言后，本轮在场角色依次调用自己的主 API。每人仍走原家园 `generateHomeReply` → 统一上下文构建、世界书、记忆范围和情绪评估，使用角色独立 API 配置。不会把几个角色的私聊、世界书和秘密拼成一份共享请求；因此也不需要跨角色世界书去重。

后一个角色看得到本轮前面已经发生的发言和实际动作。输出只能属于自己，允许 `silent:true` 保持安静；程序只执行提供给该角色的动作 ID。不会替用户生成一条用户消息，也不循环触发无限群聊。人员、房间或原发言变化时停止旧请求；中途 API 失败直接显示错误，重试跳过已保存的发言。

共同事件保存作者、房主和发生当时的参与者，分别投影到每个参与者的既有消息管线。每个人的上下文范围、记忆总结水位和归档独立；后加入的人不补收之前的经历，未在场的人不获得事件。家园秘密依赖各自已提交的消息来源，失败请求不提供来源。修改、删除事件继续遵守已有消息和秘密撤销规则。

副 API 沿用现有情绪／家园秘密／哔哔管线，不负责替所有人编一段共同生活，也不驱动这些本地动作。

## 串门流程

1. 用户可以预约；生成日程时角色也可向自己真实通讯录里的熟人提出最多一项申请。
2. 日程中的时间按发起角色时区解释，手动预约明确使用设备时间。申请最长提前七天，时长 5 分钟至 4 小时；同一访客不能同时去两家，也不能一边招待访客一边出门。
3. 房主下一次聊天／家园主 API 收到申请与文本操作说明，输出 `[[HOME_VISIT_REPLY:{"id":"申请ID","accept":true}]]` 或 JSON `homeVisitReplies`。仅房主可处理，拒绝用 `false`；不需要工具调用。SAR 只消费原始 CHAR_TRUE，思考段不能执行操作。界面也能手动同意、婉拒或取消。
4. 到时间还未答复，自动同意；同意不等于到场。目标家园必须打开、可见、房主在家、有位置且访客形象加载成功。否则等待，时间到期结束，不补写离线经历。
5. 实际到场后才写共同记录；到期或取消时在可见现场记录离开。访客在该次来访有效期间，自己的家显示正在串门。

申请和日程同事务保存，避免只有申请、没有日程。请求去重、答复和占位用 IndexedDB 事务。预约来访有 15 秒短租约，每三秒续期，避免多个页面同时认领同一预约；关闭释放，崩溃后过期恢复，恢复时仍须重新确认形象到场。它是本机多个页面之间的协调，不是跨设备联网联机系统。手动邀请是用户的场景安排，不是全设备唯一在线身份。

## 验收与边界

隔离样例：`test/fixtures/home-social-life.html`，建议独立 5190 端口，使用演示人物和本地模拟 API。不要在存有用户备份的同源页面运行会写演示数据的 fixture。

已交互验收：四人加载、访客独立活动、三角色逐个回复、第二人失败后继续重试、三人共同上下文、实际串门与取消，以及缺席角色不收到来访事件。测试覆盖事务竞争、租约过期、拉黑、错误时间、回复格式、独立来源、座位占用、离场和跨房间路径。

本次没有调用用户真实 LLM，也没有部署 Worker。真实模型的格式遵循与回复观感仍需使用实际 API 体验；无法保证每个模型总能遵守提示词。全仓 TypeScript 检查存在原有错误，不能宣称全仓类型检查通过。

双人门口通行回归：`utils/residentNavigation.test.ts` 覆盖优先绕行、狭窄处临时穿过、重叠脱困、途中重新规划和终点占用；`scripts/test-home-resident-passage.mjs` 使用 `room3d-home-social.html?room=halloween&body=blank&pair=1` 的真实双人模型检查召唤后双方点击空地移动，旁人位置保持不变。

暂不包含：多人共用一次模型请求、关闭页面后的持续模拟、跨设备实时联机、访客完整家具技能。默认逐人请求与有限本地活动是本次正式接入范围。
