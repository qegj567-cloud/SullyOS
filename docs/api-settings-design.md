# API 配置交互设计约定

## 设计意图（用户明确确认）

- 从设计角度，选择预设本来就应持续使用该预设的最新配置；同步是默认行为，不是需要理解或开启的新功能。
- 为方便用户理解，不再引入「引用」「槽位」「引用同步中」等实现概念。用户只需知道「当前使用哪个预设」和「这次修改影响哪些位置」。
- 不显示「引用同步中」状态标签：它既不是请求进度，也不是加载状态，会让人误以为正在等待。
- 修改预设时明确提示「修改会同时更新所有使用此预设的位置」，保留实际受影响的位置名单。
- 选中预设后仍直接显示紧凑的接口类型、URL、Key、模型下拉和测试连接；不得替换为摘要卡片，也不再放「编辑此预设」「复制为独立配置」中间按钮。字段修改直接保存到当前预设并同步；仅改某个位置时切换另一预设，新建可沿用原预设参数。名称、分组、删除等管理操作继续长按进入。
- UI 简化不得改掉底层按预设 ID 跟随、旧版兼容快照、删除兜底、跨用户空间更新和云端凭据同步机制。

## 布局约定

- 对话和识图共用预设库、选择面板及连接字段排版，识图只增加自身开关、测试与必要说明。
- 主界面只展示当前预设入口，底部选择面板默认全局搜索，可按分组筛选；点选后收起，长按编辑，滚动不得触发切换或编辑。
- 接口类型、URL、Key、模型到测试连接保持紧凑且可读；减少外层留白，不缩成难以点击的按钮，不用隐藏字段冒充紧凑。
- API 调用记录与「对话」「识图」并列为顶部页签；每页 5 条、列表区域固定高度，输入构成单独弹窗展示，不在记录列表内展开。
- 数据与协议行为不由视觉重排改变。占位数据只进入本地验收页面，不作为生产默认数据。

## 后续接手者

这些是用户确定的产品语义，不是临时美化偏好。后续重构或合并请保持，不要重新加回同步状态标签、引用模式选择或整页平铺的预设列表。
canary 已复用 ApiSlotEditor 的绑定和自动保存机制；后续不可用旧版配置快照替换绑定逻辑。

- 手机轻点必须覆盖 `pointerdown → pointerup → pointerleave → click`：松手后的离开事件不得标成滑动。只在按住期间监听移动和滚动，松手、取消、卸载时解除监听，不给每行常驻 document 滚动监听。
- 预设排序按数据变化缓存；搜索只过滤，不在每次输入或外层重渲染时重排全库。
- 测试推送也复用 ApiSlotEditor：默认跟随全局，临时选择保留预设绑定，只改变本轮测试；编辑预设仍影响全部使用位置，不另造一套配置组件。

- 模型列表原地下拉，刷新只更新列表，不另开选择弹窗；仍可切换手动输入。移除「存为新预设」，新建统一走「新建预设」，编辑已有预设自动保存。
- 预设修改实际保存后显示约 1.4 秒的「修改成功！」轻提示；只打开、搜索、刷新列表或无效草稿不得谎报保存成功。提示在当前面板局部渲染，不推动全局状态重渲染。

- 新建预设提供「沿用已有预设」选择面板；选中即复制整套连接参数与分组进入新草稿，不继承绑定 ID、不修改来源预设，确认创建后才保存新条目。

- 主对话没有预设时显示「您还没有 API 预设，请先新建预设」，其中「新建预设」为直接打开创建窗口的按钮，不展开空白连接表单。创建并选用后立即显示所选预设。旧独立配置仍保留，并可预填首次新建；角色、副 API 的跟随和独立配置不受影响。首次引导先指向新建入口，打开后再指向创建窗口中的地址栏。

- 保存时机：文字与数字输入仅在失焦时保存，取消停手 600ms 的定时保存；停顿不会写入或全局同步。下拉选定、开关切换、滑条松手时保存一次，离开表单兜底提交合法草稿；未改动或重复失焦不重复保存、不重复提示。
