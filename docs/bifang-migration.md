# 彼方公共后端 bifang

2026-11-16 起，公共邮局和信号坠落处迁往 `https://bifang.friedsully.com/po`。Worker 与 D1 都命名为 `bifang`，部署配置在 `worker/bifang/wrangler.toml`。原账号已失去访问权限，旧服务保持现状，不做关停、重定向或旧信件补迁。前端网站的 origin 不变，本地角色、信件留档和身份码不清理。

## 数据范围

- 新库接收新寄出的信件、回信和互动，复用 `worker/post-office/src/index.ts` 的邮局实现。
- 旧公共接口快照包含 41 首封存诗、342 行、两个册子；诗 ID、句序（包括缺号）、正文、笔名和时间戳原样保留。快照不包含旧信件或任何用户身份。
- 旧接口只提供最新册子的完整元数据。较早册子的标题/副标题/主题无法取回，使用明确的「封存诗集」标签和可核实的诗数，不把重建的册子标签当作原始数据。
- 诗句初始 `device=''`，不伪造作者。诗文读取不依赖旧服务。活动继续落幕，所有写诗端点返回 410；管理员仍可删除诗句。
- `scripts/prepare-bifang-archive.mjs <快照目录> <输出.sql>` 核对 SHA-256 后生成新库导入文件。它使用普通 INSERT，不能对已有生产库反复导入。旧快照、导入 SQL、部署结果在本机 Git 忽略的 `output/post-office-migration/`。

## 归属补回

1. 应用启动先完成 localStorage 镜像恢复，再读取已有的 `vr_po_device`。无身份时不为补回生成新身份；自建后端不参与官方迁移。
2. `POST /po/poem/recover-ownership` 只提交身份码，不上传角色姓名、本地归属表或客户端声称的作者清单。
3. bifang 向固定的旧 `noir2.cc.cd/po/poem/feed?device=…&mine=1&limit=100` 核实。禁止重定向，不接受客户端指定上游。缺失 mine 标记、格式不完整、到达分页上限、正文不匹配或已有不同归属均不记完成。
4. 只更新新库已有且正文一致的句子，不创建或复活已删除的诗句，不覆盖其他用户。更新归属和完成标记使用 D1 事务批次，按身份/归档版本保存；60 秒租约合并并发请求，失败后冷却一小时重试。
5. 成功后无需再访问旧接口。前端按后端地址、身份码和归档版本缓存完成标记，并通知已打开的纪念馆刷新；迟到的旧读取不能覆盖刷新结果。失败不阻塞公开诗集阅读，下次读取或定时重试继续。
6. 具体角色名继续读取本地 `signal_my_authorship`，随原有备份路径保存。缺少该记录时只恢复设备级「你的句子」，不猜角色。

上游已经停掉且从未补回的用户，无法保证找回归属。管理密钥不是旧 D1 导出权限；不尝试遍历用户身份。新 Worker 关闭可观测请求日志，代码不记录身份码、旧查询 URL 或诗文响应。

## 地址与发布

`utils/vrWorld/bifangConfig.ts` 为唯一公共地址与归档版本来源。默认和精确匹配的旧官方根路径 `/po` 自动切换，自定义域名或自定义路径不动；从旧备份恢复地址后也按同一规则读取。新库不复制旧管理员密钥，新生成的 `ADMIN_TOKEN` / `PO_IP_SALT` 保存在本机被 Git 忽略的 `worker/bifang/.dev.vars`，生产环境以 Worker Secret 保存。

后端先建库、导入、部署、核验，再发布前端地址切换。正常构建通过 `pnpm build:workers` 同时产出 `worker/bifang/worker.bundle.js`。后续单独部署用 `pnpm dlx wrangler@4.122.0 deploy --config worker/bifang/wrangler.toml`，不要把本目录配置用于旧后端。

回归覆盖真实 SQLite 上的核实/幂等/并发/失败重试、伪造归属拒绝、旧活动写闸、公开字段不泄露身份，以及前端地址迁移、备份旧地址、自建后端、身份切换竞态和缓存行为。
