# 本机存储用量：怎么量、怎么分类

设置「备份与恢复」顶部的用量面板（`components/settings/StorageUsagePanel.tsx`）回答两个问题：数据一共多大、都是些什么占的。测量和分类都在 `utils/storageStats.ts`。

## 一行对应一个 App

展开明细后每个 App 一行，用 App 自己的名字，按大小降序排。几样东西不属于单个 App，单列一行：

| 行 | 装的是什么 |
|---|---|
| 图片与媒体文件 | 公共图片池里的图片、音频、视频 |
| 角色模型 | 公共图片池里的 VRM / Live2D 模型文件 |
| 角色语音缓存 | 合成过的角色语音，下次念同一句话直接用，不自动淘汰 |
| 收藏 | 收藏的内容和语音 |
| 外观与系统素材 | 壁纸、图标、外观预设、字体、设置镜像等 |
| 小屋资源包 | 下载到本机的 3D 小屋资源包，可以重新下载 |
| 网页缓存等 | 浏览器报的总量减去上面各行的差额，主要是离线缓存 |

## 三张登记表

一条数据归到哪一行，依次看这三张表（都在 `utils/storageStats.ts`）：

1. **库名**（`categoryOfDatabase`）。各用户空间的主库按表名细分；协同工作、主动消息、小屋资源包这些独立的库整库算一行。独立库的表名是各自起的，协同工作库里也有 `messages` 和 `assets`，按表名判会记到聊天和外观头上，所以不认识的库整库算「其他数据」。
2. **表名**（`STORE_CATEGORY`）。主库的每张表都要登记。
3. **`assets` 表的 key 前缀**（`ASSET_KEY_CATEGORY`）。这张表按 key 存杂项，聊天语音、角色语音缓存、生成的歌、哔哔的整份数据都在里面。只列占地方的和能说清归属的前缀，没列的算「外观与系统素材」，所以这张表不用列全。

## 加新表、新 key、新库时

- **主库加表**：在 `STORE_CATEGORY` 补一行。`utils/storageStats.test.ts` 里「主库里每张表都登记了类别」会在漏登记时失败。没登记的表不会从总量里消失，只是掉进「其他数据」，用户看到的是一行说不清是什么的数字。
- **往 `assets` 表存新东西**：数据会变大（音频、图片、整份 JSON）就在 `ASSET_KEY_CATEGORY` 加前缀；几十字节的小配置不用加。
- **新开独立的库**：在 `categoryOfDatabase` 里加一条。
- **新 App**：在 `STORAGE_CATEGORY_LABELS` 加一个类别，名字和桌面图标一致。

## 测量上的取舍

- 普通表超过 300 条就均匀跳着采样再放大，界面标「约」。`blob_assets` 和 `assets` 走 2 万条的全量上限：它们的大头是 Blob，只读 `size` 很便宜；`assets` 里还有「整份数据就一条」的大记录，采样要么漏掉、要么被放大十几倍。
- 量的是数据的原始字节。浏览器落盘时会压一道文本，所以能读到实际占用时把文本部分按比例折算，Blob 不折算。
- 图片池是所有用户空间和所有 App 共用的，池里的记录不带归属，所以图片只有一行总数，不分 App、不分角色、不分用户空间。按用户空间拆分也因此暂不显示：图片全在默认空间的库里，拆出来的数字会把所有空间的图片都算给默认空间。

## 清理视图的约定

这块面板后续会长成「看占用、做清理」的视图，已经定下的两条：

- **层级**：第一层按 App，点进去再按角色。壁纸、主题这类不属于任何角色的数据在 App 一层就到底。
- **已删除角色留下的数据**：删除角色只删角色资料，它的聊天记录、记忆、日记留在本机。这些数据归到「已删除角色留下的数据」里列出来，由用户亲手清理，不在删除角色时自动连带删除。

给图片算归属需要把所有引用扫一遍（和孤儿图片清理是同一趟扫描，见 `utils/blobGc.ts` 文件头），同一张图可能被多个 App、多个角色、多个用户空间引用。
