# SAR 布告板路人群像

布告板「刷新」保留随机遇到两三位路人或一位自由活动角色的入口。路人不再使用固定句库或本地随机交易脚本，而是每次前台刷新共用一次模型调用。自家角色仍通过 runVRSession 使用原有人设和上下文；不把自家角色交给路人群像模型代演。

## 一轮流程

1. 从原来的四个路人中抽两三位，保留原 actor ID、姓名和有限钱包。读取公开的最新 24 张展板便笺、每帖最近 8 条回复、5 张近期封存便笺、当日行情与这几位路人的余额和可用库存。没有导入角色私聊、人设或用户私人资料。
2. 使用彼方全局 API，未配置则跟随聊天默认 API；不借用某角色的专属 API。一轮返回 3～8 个有顺序的动作，不按路人人数调用多次，也没有后台刷新计时器或自动重试。
3. 路人可免费发便笺、回复已有帖子、回复本轮新帖、买入、交付、挂单、发需求或撤自己的便笺。每人最多一次非回复动作，可以多次接话。新帖用 n1～n8 临时引用，后续回复映射到实际新帖 ID，所以一轮里可以互相喊话。
4. 先严格解析身份、动作、金额和前后引用，再在市场写锁内重新读取最新存档。金额、归属、挂售容量、回复容量和到期状态继续沿用原市场执行器。过时的动作跳过，依赖它的新帖回复也跳过；有效部分一起保存，界面显示跳过数量。完全无法执行则不落库。
5. 来访调用记录写到彼方 API 记录，显示「布告板路人（整轮）」。交易相关的自家角色仍能收到真实事件回执，路人不能直接替用户发言、付款或决定自家角色的回复。

## 数值与退出边界

四个路人仍各自仅有一次初始余额，不刷新补钱、不创建新身份领钱。没有可用库存的路人可得到一件程序抽出的候选鱼获，只在模型确实选择挂售且挂售校验通过时写入；模型不能自造实物，失败的挂售不留下免费库存。吹牛、承诺和玩笑商品不会直接增加金钱或物品。

错误 API、空回复、无效 JSON 或未知身份不回退模板。重复点击和其他标签页正在生成时拒绝开启另一轮；生成锁和市场写锁分开，用户仍可在其他页面交易。离开整个市场浮层会取消请求，关闭 NPC 或已取消的一轮在写入前再次检查，不再补写。关闭 NPC 时，随机刷新只会尝试已开启自由活动的自家角色；没有合适角色则提示，没有路人模型调用。

零酬谢的 favor 继续使用原便笺格式（不迁移旧档），列表显示「便笺 / 留句话」，详情不展示酬谢 0。回复仍不结算；提交完成文字约定会封存该便笺。

## 代码与回归

- `utils/vrWorld/marketNPCs.ts`：现场快照、群像提示词、JSON 校验、顺序动作执行。
- `utils/vrWorld/marketNPCSession.ts`：API 选择、整轮调用、跨页互斥、取消与新鲜状态保存。
- `FishingMarketOverlay.tsx`：沿用刷新与指定角色入口，显示来访中、失败及部分动作未执行的状态。
- `utils/marketRefresh.test.ts`：整轮多位路人、新帖引用、有限钱包、非法身份和资源、API 失败、取消与并发。
- `scripts/test-sar-board-refresh.mjs`：隔离浏览器模拟 API，验证多角色帖子/回复实际渲染、一轮一次请求、指定角色原流程、错误时不补帖子与小屏。模拟台词仅在测试里，正式代码不包含示例句库。
