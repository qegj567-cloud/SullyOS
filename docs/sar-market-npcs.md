# SAR 布告板路人群像

布告板「刷新」保留随机遇到两三位路人或一位自由活动角色的入口。路人不再使用固定句库或本地随机交易脚本，而是每次前台刷新共用一次模型调用。自家角色仍通过 runVRSession 使用原有人设和上下文；不把自家角色交给路人群像模型代演。

## 一轮流程

1. 从四个有限结算钱包中抽两三个槽位。模型通过 `personas` 生成临时路人的姓名与身份；有未封存帖的槽位保持原人物，新人物不重置钱包，老帖保留当时姓名。读取公开的最新 24 张展板便笺、每帖最近 8 条回复、5 张近期封存便笺、当日行情与余额和可用库存。没有导入角色私聊、人设或用户私人资料。
2. 使用彼方全局 API，未配置则跟随聊天默认 API；不借用某角色的专属 API。一轮按顺序返回动作，每位实际来访者至少一个、整轮最多八个，不按路人人数调用多次，也没有后台刷新计时器或自动重试。
3. 路人可免费发便笺、回复已有帖子、回复本轮新帖、买入、交付、挂单、发需求或撤自己的便笺。同一路人可在本轮连续发帖、交易和接话，每步仍按最新余额、库存和展板容量校验，不因同一人先发事件再挂售而拒绝整轮。新帖用 n1～n8 临时引用，后续回复映射到实际新帖 ID，所以一轮里可以互相喊话。
4. 先严格解析身份、动作、金额和前后引用，再在市场写锁内重新读取最新存档。金额、归属、挂售容量、回复容量和到期状态继续沿用原市场执行器。过时的动作跳过，依赖它的新帖回复也跳过；有效部分一起保存，界面显示跳过数量。完全无法执行则不落库。
5. 来访调用记录写到彼方 API 记录，显示「布告板路人（整轮）」。交易相关的自家角色仍能收到真实事件回执，路人不能直接替用户发言、付款或决定自家角色的回复。

## 路人短事件

`encounter` 动作在同一次生成中写出公开 `title/words` 与隐藏 `event.story`。`mode=buy` 是玩家支付标价，`work` 是路人支付酬谢，`free` 只允许零价。按原挂单/文字需求结算，不新增实体物品、额外奖励或第二次模型调用。故事建议 80～240 字、2～5 句，有具体细节与短小落点；题材自由，避免套用固定案例、长篇任务与每帖强行升华。临时 NPC 不冒充用户角色或常驻 NPC。

用户打开帖子只看到招牌，买下/接活后就地展开故事；参与过的帖子收入自己的「往期便笺」。角色上下文收到帖子和预写事件，可选择一帖并给出 `REACTION`；程序成交成功后才展开 `{{participant}}`、记录反应，并通过既有活动卡片和事件回执保存。余额不足、到期、已被买走不会记录事件或反应，回复帖子也不会触发。用户和角色共用一次性成交逻辑，重复参与不重复扣款或发钱。

其他 NPC 只能看到事件帖的公开部分，不会代替用户或角色买走。新一轮可读取近期已完成事件写偶尔的后续或关联视角，未触发故事不会作为既成事实传给路人模型。数据随现有 SAR 备份保留。

## 数值与退出边界

四个结算钱包各自仅有一次初始余额，不刷新补钱，临时人物换名也不重新领钱。没有可用库存的路人可得到一件程序抽出的候选鱼获，只在模型确实选择挂售且挂售校验通过时写入；模型不能自造实物，失败的挂售不留下免费库存。吹牛、承诺和玩笑商品不会直接增加金钱或物品。

错误 API、空回复、无效 JSON 或未知身份不回退模板。重复点击和其他标签页正在生成时拒绝开启另一轮；生成锁和市场写锁分开，用户仍可在其他页面交易。离开整个市场浮层会取消请求，关闭 NPC 或已取消的一轮在写入前再次检查，不再补写。关闭 NPC 时，随机刷新只会尝试已开启自由活动的自家角色；没有合适角色则提示，没有路人模型调用。

不带事件的零酬谢 favor 继续使用原便笺格式（不迁移旧档），列表显示「便笺 / 留句话」，详情不展示酬谢 0。回复仍不结算；提交完成文字约定会封存该便笺。

## 回复格式兼容

兼容完整 JSON 外的解释/代码围栏、末尾逗号及字符串内未转义换行/制表符；清理只针对表现格式，不补齐截断 JSON，不猜测金额、身份、动作或引用。正文中的标点原样保留。API content 文本块沿用通用提取器；finish_reason=length 明确报告截断且不执行。

标题、公开正文和隐藏故事不再因超过40/600字拒绝整轮；篇幅仅作写作建议。保存便笺/回复取消默认240字截断，事件结算取消1200字故事和600字反应截断，完整正文随备份保留。现场提示词仍使用有限长度摘要控制上下文，不修改存档正文。已在现场的路人身份以本地快照为准，模型改写不会覆盖或导致整轮失败；personas 可省略已有身份，但仍拒绝未知/重复身份及无身份的事件。原金额、资源归属、动作数量和顺序引用校验保留。

解析/落库成功后才记录来访成功，格式错误记录具体阶段（JSON、personas 或动作编号），不记录私人正文。没有自动重试，不会额外消耗 API 次数。

## 本次返回

布告栏本次失败的模型 content、finish_reason 和 usage 仅由错误对象传到当前页面内存，在失败提示下展开查看和复制；不写入彼方调用历史、IndexedDB 或 localStorage。下一轮刷新立即清空，关闭布告栏或刷新页面后丢弃。调用记录只保留原有状态和简短错误。无模型返回的网络失败不编造原文；不包含请求头、API Key 或 reasoning_content。
