# 见面挂起与离开提醒

见面对话进行到一半时走开，见面先挂起，回来能接着见；按角色打开「离开提醒」后，走开超过设定的时间，角色会在私聊里发一条消息找用户。

## 什么算离开

| 用户做了什么 | 见面 | 离开提醒 |
|---|---|---|
| 对话阶段按主页、用悬浮球回桌面、打开别的 App | 挂起，顶部出现「见面中 · TA」条，点一下回到原来的画面 | 计时 |
| 对话阶段切出 SullyOS、锁屏 | 页面还在，回来照常继续 | 计时 |
| 点结束、用返回手势退出见面 | 结束 | 不计时，已备好的撤掉 |
| 感知阶段（还没开口）走开 | 照旧结束 | 不计时 |
| 回到见面 | 恢复 | 取消这次 |
| 在私聊里和 TA 说话 | 仍挂着 | 取消这次 |

一次离开最多发一条。

## 挂起

挂起只存在内存里（`OSContext` 的 `suspendedDate`），刷新页面或关掉网页后就没了，和通话挂起一样；挂着时网页更新不会自动刷新页面。

- 对话画面（`components/date/DateSession.tsx`）每次渲染把当前状态写进 `snapshotRef`：播到哪一句、剩下的台词、立绘、观测、阅读模式、还停在开场白上没有、没发出去的草稿。
- 见面在对话阶段被卸载、且不是点结束退出的，就挂起（`apps/DateApp.tsx`）。点结束时先记下「主动结束」，从聊天进来、点结束回聊天那条路也不会挂起。
- 从任何入口打开见面都会回到挂着的那场，当前角色一起切回去；从聊天点「见面」进同一个角色，也回到那场。别处另开一场见面时，挂着的那场直接扔掉。
- 记录在恢复后才异步读回来。读回来的还是挂起时那条回复，就停在原来那一句；不一样说明离开期间回复到了，接着播新的。
- 切走时回复还在生成：请求照常跑完并落库。恢复后画面显示「正在输入」、不让重试（免得同一句发两次），等那次请求落定后再读一次记录。

## 设置

见面设置（`components/date/DateSettings.tsx`）的「离开提醒」分区，按角色存在 `CharacterProfile.dateLeaveReminder` 上：开关默认关，等待时长 1 到 60 分钟，默认 5 分钟。导出角色卡时剥掉，导入独立用户时关掉。

## 两条路，按角色二选一

| 角色状态 | 走哪条 | 覆盖的情况 |
|---|---|---|
| 开着主动消息 2.0，且配了 Worker | 云端任务 | SullyOS 内走开、切出 SullyOS 都覆盖，到点推送 |
| 其余 | 本地计时 | 只覆盖 SullyOS 内走开、页面开着的情况；页面一隐藏就不再计时，也不补发 |

判定和离开后消息共用 `isAwayCloudRoute`，只有这一处。开了 2.0 的角色，在 SullyOS 内走开也交给云端，避免本地发了一次、云端又推一次。

### 云端

任务在人进入见面对话时就备好，不在走开那一刻建。iOS 切到后台后页面脚本几秒内就会被冻住，建任务要上传快照、登记推送，赶不及。

- **备好**：进入对话、从挂起恢复、页面回到前台时，把这条任务改期到「现在 + 等待时长」，远端已经没有（上次走开时发过了、被取消了）就新建。任务 metadata 带 `amsgDateLeave` 和 `amsgDateLeaveDelayMinutes`，记录上 `dateLeave: true`，不占任务名额。
- **人还在见面里**：见面开着且页面可见时，客户端一直续「见面中」租约（`chat_presence`，`scene: 'date'`）。worker 到点按租约最后一次续上的时刻，推迟到「最后一次见到人 + 等待时长」，不消费任务、不占重试、不留痕。人一走开租约不再续，时间一到就发。
- **页面隐藏也停租约**：桌面浏览器的后台标签计时器只是变慢，不停的话租约会断断续续续上，提醒就一直发不出去。
- **撤掉**：点结束见面、在私聊里对这个角色开口、关掉或改了这项设置时，取消云端那条。取消没发出去时，worker 到点看到租约被私聊盖成了聊天场景，也会作废，不留回执。
- **生成到一半人回来了**：推送前的复查照常生效，回到见面记成 `in-person`，开了口记成 `chat-overlap`。

### 本地

在 SullyOS 内走开（见面被挂起）时开始计时。页面隐藏就作废；到点时页面还开着、走开后也没在私聊里说过话，才用聊天同一套上下文生成一条（`runLocalProactiveTurn`，和离开后消息共用），落库消息带 `dateLeaveReminder: true`。生成期间回到见面或开了口，这条作废。

## 为什么不受连发和每日上限拦

聊天的离开后消息计入「没回时最多连着找几次」，是因为它在聊天语境里生成，角色这一轮能顺手给自己排下一条，用户不回时会一路排下去，需要同一个计数把这条链拦住。

离开提醒是用户为这次见面设的一次性提醒：一次离开只发一条，发多频繁取决于用户自己进出见面的次数，生成这一条时也不给角色排程工具，不会再带出后续。没有那条链要拦，所以它到点必发，不看连发上限，也不看每日上限。

它发出去仍然照常记进角色的发送记录和当天的发送次数：角色之后知道自己发过这句，之后自己排的消息也把它算作一次「没回」。它本身不被上限拦，但会占后面的名额，用户一直不回时，角色不会因为多了这条提醒就多找一次。

## 改这块时要一起动的地方

| 改什么 | 位置 |
|---|---|
| 挂起、恢复、什么时候备好和撤掉 | `apps/DateApp.tsx`、`context/OSContext.tsx` |
| 画面状态交出与恢复后的接着播 | `components/date/DateSession.tsx` |
| 顶部「见面中」条 | `components/PhoneShell.tsx` |
| 云端任务的备好 / 撤掉、本地计时 | `utils/dateLeaveReminder.ts`（有单测） |
| 指令文案、metadata 键 | `utils/amsgFireSchedule.ts` 的 `buildDateLeaveInstruction` |
| 按租约推迟、不受上限拦、不给排程工具、必发 | `worker/amsg/src/index.ts` 的 `onBeforeFire` |
| 私聊开口时撤掉 | `hooks/useChatAI.ts` |

worker 有改动时先部署 worker，并把 `utils/amsgBundleVersion.ts` 往前推一版。
