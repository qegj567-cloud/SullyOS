# 主动消息 2.0 · 设置页的引导与面板

系统设置里「主动消息 2.0 → 配置」打开的那个弹窗（`components/settings/ActiveMsgGlobalSettingsModal.tsx`）有两副样子：**引导**和**面板**。两边摆的是同一份内容，只是外面的壳不同。

## 什么时候看到哪一副

| 打开时的状态 | 看到的 |
|---|---|
| 还没连上后端 | 引导：介绍页 → 装后端 → 开通知 → 即时对话 → 给角色开启 |
| 已经连上 | 面板：每块一行「标题 + 状态」，内容平时收着 |

判断只在配置读回来的那一刻做一次，之后只由用户点按钮切换（引导里的「跳过引导，直接看全部设置」、面板底下的「重看介绍」）。引导走到一半连上了后端，人还留在引导里；这时候要是跟着「已连接」实时切换，后面几步就被跳过去了。

没有另存一个「引导看过没有」的标记：连没连上本身就是答案。引导中途关掉、之后再打开的人如果已经连上，会直接进面板，没做完的那几块会自己展开。

## 引导

- **介绍页**：`AmsgIntroDemo` 是一段纯 CSS 的循环演示（聊天 → App 被杀后台 → 桌面弹出通知），不读任何数据；系统开了「减少动态效果」时停在最后一帧。下面三行说它能做什么，再下面是要准备什么、数据存在哪。
- **数据去向在动手装之前说**：消息内容、提示词和 API Key 会进用户自己的 Worker，这件事放在介绍页，而不是等装完了才在面板的折叠区里看到。面板里的「数据存在哪儿」是同一件事的完整版。
- **第 1 步没连上不放行**：后面几步都要问这台后端，跳过去只会看到一排开不了的开关。第 2 步（通知）可以跳过，第 3 步（即时对话）本来就是可选的。
- **第 1 步里地址和密钥那几栏平时不出现**：只有展开了「我要手动配置」，或者一键部署已经把地址填好、正在等它生效时才摆出来。已经在别的设备上装过后端的人走「去全部设置里填」。
- **「给角色开启」单独占一步**：全局配好只是「能用」，角色那边的开关不开的话一条都不会来，而且每个角色都要各开一次。这件事跟即时对话挤在同一屏容易被当成附注略过，所以放在第 4 步，只讲去聊天页「+」→「主动消息 2.0」打开开关这一件事。这一步没有可操作的控件，开关在角色的聊天页里。

## 面板

每块用 `FoldCard` 包着，标题行常驻状态，内容点开才看。

- **有事要处理的块自己展开**：后端没连上 / Worker 过旧 / 后台任务暂停着，推送没开或查不出来。
- **只自动开、不自动关**：刚办完的那一步下面往往还挂着下一个要点的按钮（开好通知之后的「发送测试通知」），办完就收走会让人找不到。
- **即时对话那块不自动展开**：「Worker 认不认即时对话」是异步探出来的，探到之前跟「不支持」分不出来，按它展开的话每个正常用户打开面板都会被弹开一次。状态那几个字变黄（「已开启 · 暂不生效」）就是提醒。

## 即时对话的说法

「即时」容易被读成「秒回、不走模型」。所以凡是解释它的地方，第一句都先说清：回复照样由模型现写，等多久、花多少 API 费用都和平时一样，变的只是在哪儿写（本机页面 / 云端后端）。然后才讲开和关各自意味着什么，直接用「杀后台」这个说法：关着时 App 被杀后台回复就断了，开着时杀后台也照样收得到。角色面板里那一行说明用的是同一个说法。

## 往里加新板块

把内容写成一个 `xxxBody` 常量，面板里用 `FoldCard` 包一层；只有新用户第一次配置时必须经过的东西才进引导，进的话加到 `GUIDE_STEPS` 并给它一屏。排障、维护类的东西（体检、更新 Worker、暂停后台任务、云端数据）只放面板。

测试在 `utils/activeMsgSettingsModal.test.ts`：没连上先看到介绍、连上直接进面板且各块收着、推送没开时那一块自己展开、引导走到即时对话那步说清它不是秒回、最后单独一步讲给角色开启。
