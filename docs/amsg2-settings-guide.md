# 主动消息 2.0：连接、换机与设置

## 界面原则

设置页只保留一个「主动消息 2.0」入口，进入全屏工作区。采用浅紫底色、顶部横向导航、紫色操作按钮与可读字号；通知页直接呈现接收方式和设备状态，技术字段收进维护区，不再套层层小弹窗。

顶栏保持近白底色、居中的标题与轻量返回按钮；按最新视觉参考，主导航用文字、淡紫选中底和短细下划线标记当前分区，不加装饰图标或竖分隔线。键盘焦点有独立描边。

所有全屏子页共用 `SettingsDetailPage` 的 `--chrome-top` 顶部留白，与交换日记、彼方等 App 一致，同时避开系统安全区和 SullyOS 时间／电量栏。状态栏隐藏、紧凑和 iOS contain 模式沿用外壳变量；不硬编码 44px，也不在嵌入面板再加一份留白。

内容顺序是当前状态 → 下一步 → 维护细节。顶部三项为「功能总览」「通知与设备」「功能设置」。总览集中放「主动消息 2.0 总开关」「即时对话总开关」和当前用户的角色配置入口。两个开关在同一张卡片中，即时对话轻微缩进、标题前加短竖线，两只开关右侧对齐；开关外观为 36 × 22px，点击范围保留 44 × 44px。关闭 2.0 时，即时对话控件置灰，恢复时沿用其原选择。角色整行可点击，状态在窄屏自然换行。功能设置依次为「连接与迁移」「后台地址与维护」「运行体检」「云端数据」「高级维护」。修改域名、重新验证、更新后台等直接放在独立维护分区；首次连接与重新配置向导仍保留必要的连接表单。数据去向、个人换机备份及分享注意事项合并在「连接与迁移」底部的「数据与备份说明」中，以小字号附带说明直接展示，不折叠；配置前的数据去向短说明仍直接显示。VAPID 在高级维护中，一键部署用户无需接触它。

主动消息全屏页的内容和横向分区隐藏滚动条，保留原生滚动，不拦截触摸、滚轮或键盘事件；窄屏分区可横向滑动，键盘切换仍将选中项滚入视野。

动效仅用于全屏进入、内容切换和按钮反馈；减少动态效果时停用。切换导航不保存、部署、注册通知或发送测试消息。表单由同一配置组件持有，主导航切换保留草稿与引导进度；异步检查不抢走用户正在看的分区。

切换分区或引导步骤时，在绘制前只将最近的 `.amsg-detail-scroll` 归零，保留内容区顶部 padding。不要对正文调用 `scrollIntoView({ block: 'start' })`：长页会滚掉留白，短页无法滚动，导航便随内容高度上下跳，还可能带动外层页面。

总览按紧凑的 iOS 设置列表排版：两行各 48px，只放名称和开关，去掉装饰图标；即时对话缩进 16px，两只开关右侧对齐。两个简介放在卡片下方的两行小字里，正常状态不另写「已开启／默认跟随」，只在未配置、暂停或未就绪时补充提示。功能区别、全局与角色开关的关系、暂停保留设置等说明放进展开项，避免常驻说明占满页面。

未连接（缺少完成连接标记或后台地址）时，首次进入自动落到「功能设置 → 连接与迁移」。用户仍可查看总览、通知和后台地址与维护；这些页面顶部都保留可点击的连接引导，其余内容由 `disabled` 字段组和 `inert` 禁用，并整体置灰，不只做视觉禁用。手动切页不会反复强制跳转。已连接但总开关暂停不属于未连接，不要求用户重新配置后台。维护页编辑地址时，临时清空输入仍保留编辑能力；清空确认与保存沿用原行为。

顶栏和选中的导航已经说明当前位置，正文不再重复「功能总览」「通知与设备」「从这里开始」等大标题。连接入口仅保留必要的引导短句；已连接时直接显示状态和后台地址。

角色列表沿用神经链接的 `CharacterGroup` 与角色 `groupId`，不另建分类。分类与名称搜索可叠加，搜索兼容大小写、全半角与多个关键词；已删除分类的角色归到未分组。每页最多渲染 12 位，支持前后翻页和页码选择；搜索或分类变化回第一页，返回角色子页保留筛选和页码，删除导致页数缩小时收回有效页。

角色名称索引按角色数据变化缓存，不在每次输入时重新标准化全部名称。搜索框即时更新，结果用 `useDeferredValue` 延后计算；结果更新期间暂时禁用分页。角色行仅接收显示所需的值并使用 `React.memo`，仍随共享角色状态更新。分区首次访问时才挂载，访问后保留组件，避免切页丢失草稿、分类或页码。

左上角返回、Escape 和系统返回共用逐层返回逻辑：确认窗口 → 连接码预览／生成表单 → 换机入口或引导上一步 → 主动消息工作区 → 系统设置。连接码预览返回后保留输入，不触发验证或保存；隐藏分区和被覆盖的表单不拦截返回。云端数据及 VAPID 是完整子页，返回原功能分区；同级标签页不形成新的返回层级。底层设置不可交互，退出恢复入口焦点和滚动位置；清理、暂停等原有最终确认和业务约束保留。

Worker 开着、或近 7 天内开过救援模式时，内容区最顶部常驻一块红色提示，所有分区和引导步骤都看得到，用户确认过全局弹窗也不收起，过了 7 天窗口才消失。它只放一句短文案和「查看详情」：完整留痕和处置清单统一在全局弹窗（`components/AmsgRescueAlert.tsx`）里，重新打开同样要读满 10 秒，两处不各写一份。判断窗口与本机留存见 [amsg2-rescue.md](amsg2-rescue.md)。

## 用户路径

| 情况 | 页面与操作 | 实际范围 |
|---|---|---|
| 第一次使用 | 功能设置 → 连接与迁移 → 第一次使用 → 填 Cloudflare Token → 一键部署 | 自动创建后台、密钥和数据库；之后开启通知，完成引导进入总览分别配置角色 |
| 已经配好 | 默认进入功能总览，显示两个全局开关和角色选择 | 连接与迁移显示连接摘要及换机入口；自定义域名和验证／更新操作放在相邻的后台地址与维护 |
| 换设备，不搬聊天数据 | 原设备生成连接码 → 新设备选择已有后台／换设备 → 读取连接码 → 验证并连接 | 沿用 Worker、共享密钥、原 userId 及可用的主密钥副本；不复制角色或聊天 |
| 新设备只记得 CF Token | 已有后台／换设备 → 查找已有部署 | 只读查找有权限的账号、指定名称的 Worker 和访问地址；不重新部署、不重置数据库 |
| 恢复个人备份 | 导出前勾选包含后端连接，恢复时同意恢复连接 | 地址、密钥、userId 一起恢复；新设备仍要检查通知 |
| 备份没带连接 | 回原设备复制连接码，或重新导出带连接的个人备份 | 不能靠新设备随机生成的 userId 自动认领旧任务 |
| 迁入独立用户 | 使用既有迁入入口 | 保留目的地的全局后台，不接续来源云端任务；见 user-spaces.md |
| 原设备、连接码和带连接的备份都没有 | 选择「重新部署，不接续旧数据」并确认所选后台 | 更换该 Worker 程序、密钥和数据库绑定；不冒充恢复旧身份或旧任务 |
| 错把换机当首次部署 | 同名 Worker 检查阻止继续部署，自动转到并展开「查找已有部署」，沿用刚填的 Token 和 Worker 名称执行只读查找 | 不覆盖已有 Worker，也不因换设备清空旧 D1 |
| 配置混乱，想重新开始 | 连接与迁移 → 重新配置 → 保留后台重新配置 / 后台也重新部署 | 前者重新检查连接、通知、即时对话和角色开关；后者先查找、确认后台，再重建并走完相同引导 |

### 重新配置

未完成连接和已经连接的页面都有独立的「重新配置」按钮，不需要先清空地址或密钥。选项页使用紧凑的两行可点击列表；进入、返回和取消选项本身不保存配置、不部署、不清理云端。选择「保留后台，重新配置」后，第一步直接展示现有地址和连接验证，也可以改用连接码或备份。旧的 `initializedAt` 不足以放行：当前地址与共享密钥必须在本次向导验证成功，修改它们或连接失败会再次禁用下一步。后续复用通知、即时对话和角色设置步骤；字段的保存规则保持原样。

选择「后台也重新部署」后直接展开 Token 查找，省去无关的连接码输入。先只读查找，再选定账号和 Worker，最后确认重建；不是点击入口就清空。确认范围包括旧设备要重新连接、全局后台为各用户空间共用、旧云端任务不接续、本机角色和设置保留。重建沿用下文的独立 D1 / 新密钥计划，失败保留计划供重试；即使本机曾经连接过旧后台，也不能以旧成功标记跳过失败步骤。部署和连接成功后继续检查通知、即时对话和角色开关。

返回顺序为重建确认 → 查找 → 重新配置选项 → 原连接页；逐项重配时则先退回上一步，第一步返回选项。部署与连接进行中不能点下一步跳过。进入向导不会自动暂停旧后台；仅检查本机配置时，已有云端任务仍按原设置运行。

### Token 与连接码不是同一件事

Cloudflare Token 用于管理部署，不能通过普通 API 读取已有 secret 的值。查找支持一键部署默认名称 `sullyos-amsg`，自定义名称可以输入；多个账号分别列出，不默认取第一个。读取失败、权限不足、未发现部署分别说明，不能把失败当成不存在。一键部署明确返回已有部署时，自动带入 Token 展开查找并定位到该区域；只触发一次，切页回来不重复查找。失败时保留输入供重试，普通部署错误不触发跳转。查找只读，Token 仅留在本次页面内存，供后续重试或明确确认的重新部署沿用；退出工作区即丢弃，不写浏览器存储。查到后收起输入表单，直接呈现「用连接码接回」「从备份恢复」「重新部署，不接续旧数据」按钮，焦点与滚动落在操作区。连接码按钮进入填写界面，返回保留查找结果；备份按钮展开系统原有的备份与恢复区域，并滚动、聚焦到「导入备份」按钮。仍使用原 `/cf-api` 代理。

连接码以 `SULLY-AMSG2:` 开头，仅包含地址、原 userId、共享密钥和可用的主密钥副本。它不是加密保险箱：持有人能够访问后台，界面在生成前说明只传给自己的设备。明确排除 Cloudflare Token、模型 API Key、角色、聊天和设备订阅。旧手动部署没有本地主密钥副本也可连接，通知公钥仍由现有客户端从 Worker 取得。

接收时先本地解析、预览地址，允许换为自己的 HTTPS 域名。只有点击「验证并连接这台设备」才调用已有只读 `/get-user-key` 进行鉴权，验证通过后保存原身份，再走现有 `ActiveMsgClient.connect()`。错误连接码、错误鉴权和预览本身不改本机连接。连接阶段失败会保留已经验证的连接供重试，不声称完成。

重新部署只在选定后台并最终确认后执行。多账号不默认选择；确认绑定账号与 Worker 名称，执行前再验证目标仍是主动消息后台。优先沿用查到的自定义域名，创建新的独立 D1 并生成新密钥，不查询或清空旧数据库、不删除本机聊天；旧设备需重新连接。普通首次部署仍禁止覆盖同名 Worker，旧库缺密钥时的显式清空流程保持原约束。

### 停止旧后台与中断恢复

重建采用停止 → 等待 → 启用，而不是上传后立即接新任务：

1. 校验目标、下载包并保存本机恢复计划，创建独立新 D1。保存失败不继续修改 Worker。
2. 在同名 Worker 部署临时维护程序：HTTP 统一返回 503，不接任务；scheduled 不执行；保留即时对话 DO 类但 kick/alarm 不生成消息。上传指定 `code_update_strategy: immediate`，不等待旧 DO 延迟更新。移除 cron 并重新读取确认其为空，同时核对部署标记及新 D1 绑定。
3. 只在新 D1 的 `sully_redeploy_guard` 表登记服务器时间，等待 31 分钟。依据是 [Cron 变更最多传播 15 分钟](https://developers.cloudflare.com/workers/configuration/cron-triggers/)、[已启动 scheduled 最多运行 15 分钟](https://developers.cloudflare.com/workers/runtime-apis/handlers/scheduled/)，另留 1 分钟传播余量。旧版本不需要预先具备停止协议；不拿浏览器倒计时或查询失败冒充停止成功。
4. 用户点击「检查并继续重新部署」后读取云端进度。未到期返回剩余分钟，不启动新后台；到期后才上传正式程序并恢复 cron。已经提交给外部推送服务的通知不可撤回，仍可能晚到；独立的其他 Worker 不在本次操作范围内。

恢复计划（操作编号、新数据库 ID、新密钥）存入 ActiveMsg 的 kv，按账号和脚本名隔离；Cloudflare Token 不进本机存储。计划与首页续接提示同事务保存，重新打开「连接与迁移」会出现「继续重新配置」，自动带入原 Worker 名称，Token 需重新填写。新凭据保存到正常连接配置后清除恢复计划。维护 Worker 的普通变量只记录不含密钥的操作标记，查找时识别为「后台已暂停／继续重新部署」。即使换设备或关闭页面丢了内存，也能凭 Token 查找、沿用等待记录和新库继续，不重新创建数据库或重置等待时间；暂停期间新库没有用户任务，丢失本机新密钥时可以重新生成。

失败时不会自动回滚并重启旧后台。停止状态、cron、D1 查询或时间记录无法确认时直接阻止启用；已暂停的后台继续保持暂停供重试。正式上传失败后仍沿用同一计划重试。Web Locks 防止同一浏览器的多个页签同时操作同一个后台；外部手动部署改变标记或绑定时拒绝把异常状态当完成。只有当前选择的后台受到影响，不能声称自动停止所有账号里的独立副本。

部署标记另含不包含密钥的凭据批次编号。另一设备续接并启用后，原设备的过期恢复计划不得把旧密钥覆盖回去；此时清掉过期计划并引导重新查找接回。启用前再读一次标记和 D1 绑定，不能直接沿用等待开始前的读取结果。

连接码不能恢复本机角色与聊天历史；云端不承担整机备份。当前每个 userId 只有一个推送订阅，新设备登记会替换原通知接收位置，连接前明确提示。不要声称多台设备会同时收通知。

## APK 通知状态

通知接收方式用原生单选组呈现，明确标注「二选一」和「选择一种即可，不需要两边都开启」。只为当前选项显示「已选择」及对应配置；选择状态不等同于通知已经连接。每个引导／面板实例使用独立的单选组名称，隐藏分区不能改变可见分区的选中态。

界面按用户接收方式分类：APK 的「系统推送」置灰，并说明该项用于网页 / PWA；当前 App 需要第三方接收方案。ntfy（UnifiedPush）与 WxPusher、Bark、MeoW 一起列在「第三方推送 App」下。这是前端分类调整，不改存储枚举或消息管线：ntfy 沿用现有 `web-push` 配置对应的 Android UnifiedPush 路径，其他服务沿用原 `third-party` 路径。APK 打开页面或点击已选中的第三方分类不会自动切换现有通道或重新登记。

APK 使用现有 `getPushStatus()` 和原生 endpoint 检查，不能调用浏览器诊断后把 Service Worker、浏览器订阅等不适用项标红。系统权限、ntfy 连接和云端登记分别显示。读取失败是「暂时无法确认」，不等于没有订阅。

网页的第三方列表也显示「ntfy · APK 自动连接」，点开说明回 Android App 使用原有 UnifiedPush 连接；浏览器不伪装成能注册原生通道，查看说明不保存 `ntfy` 为第三方枚举、不覆盖凭据、不登记订阅。不新增手动 Topic 通道。

正常 APK 显示已开启；有订阅但缺系统权限显示「已连接 · 待允许通知」。说明只要求保持 ntfy 后台运行并允许 App 通知。已连接时按钮为「重新连接通知」。第三方推送保持现有渠道逻辑，网页保留原有浏览器诊断、修复路径；没有新增推送或消息生成管线。

补收零条只意味着暂无可补收消息，不能以此证明通知通路正常。设备状态进入即展开并读取，隐藏页面不轮询。首次配置未连后台时，通知操作不可用并指向连接入口。

## 引导与功能

首次配置继续沿用四步：装后端 → 开通知 → 即时对话 → 给角色开启。第一步没连上不能放行；通知和即时对话可跳过。已存在后台有独立换机入口，不要求清空地址重装。数据去向在开始部署前说明。

「大陆连接优化」保留在首次部署和连接维护中，沿用官方来源门禁、5 秒确认和令牌填写规则；连接码不带中转令牌，新设备沿用本机已配置并明确同意的中转设置。详见 `amsg2-relay.md`。

即时对话仍由模型现写，等待时间与 API 费用照常；改变的是生成运行在本机还是云端。不能让用户把「即时」理解为秒回。开关沿用连接、通知权限和后端能力门禁。

总览的即时对话开关是全局默认：角色未单独关闭时跟随全局，角色明确关闭的选择不会被全局开关覆盖。角色的主动消息排程与即时对话独立，可以只开其中一种；全局总开关暂停时，两条云端路径都暂停，角色选择保留。列表展示保存的角色选择，并明确说明暂停期间不会生效。

总览中点击角色「配置」进入完整子页，复用聊天「+ → 主动消息 2.0」的同一组件、函数式保存和云端任务清理流程，不通过列表直接翻转配置位。主动频率也使用完整子页，返回顺序为主动频率 → 角色配置 → 功能总览。聊天里的原入口继续可用。角色列表来自当前用户空间，全局连接与开关仍遵守原共享范围。

角色面板共用总览的紧凑开关样式：两行各 48px，36 × 22px 开关，仅留一行同步说明和必要的未就绪／未保存提示。角色的排程与即时对话仍可独立选择，不能把角色排程关闭误当作关闭即时对话。主动频率独立成区；「手动安排 · 可选」通过「新建定时任务」进入单独表单，默认页不展示时间、内容或创建任务的提交按钮。编辑已有任务也进入此表单，返回只退回角色设置；提交复用原排程、替换和失败恢复逻辑。聊天的原弹窗保留，避免叠加第二个小弹窗。

手动安排的发送方式显示为「固定内容／指定话题／自由发挥」，分别说明直接发送原文、不经 AI 生成；结合最新聊天上下文按指定话题生成；结合上下文、人设与当前时间自主选话题。AI 模式注明使用最近成功同步的聊天内容，不使用「聊天快照」术语。自由发挥的补充灵感默认收起，编辑已有灵感时展开；指定话题使用「这次想聊什么」输入框。底部 API 费用说明仅在 AI 模式显示。界面名称改变不改变 fixed / prompted / auto 数据值或生成指令。

频率面板与摘要使用「未回复时主动联系」，单位为「次」，解释一次联系可包含多条消息、用户回复后重新计数；子页退出按钮明确写「返回角色设置」，保存仍需点击「保存」。

频率控件按紧凑设置行呈现：标签与 34px 高的下拉框同排，开关复用 36 × 22px 的总览样式；说明留在行下。`allowSelfRecurring` 与 `allowSelfForce` 是已有的角色自排权限，不是本轮新增，显示为「允许每天／每周重复」「允许到点必发」。角色面板常驻「消息排期」，没有任务时显示「暂无排期」，关闭角色排程后仍保留该区和旧任务的清理入口。

即时对话首次开启后展示发送说明（本设备确认一次，之后仍可点「发送中」查看）。说明使用聊天气泡示意，强调普通聊天同样需要整理上下文，不能把全部准备时间说成云端新增延迟。聊天中进度贴在用户消息时间左侧；准备、上传都显示小型「发送中」，纯 CSS 点状动效，不轮询、不逐帧更新 React。云端有效回执后消失，失败显示「发送未确认」，能力不足等转本机时显示「本机生成」。后两者不代表可以关闭 App。

状态由请求生命周期持有，切出聊天再进入仍可见；旧请求收尾不能覆盖新请求状态。只有 `sendInstantChatTurn` 成功（底层确认 202 与 UUID）才算上云完成，不能用「情绪更新中」判断。强退页面前未完成的准备不承诺恢复；在 App 内换页并不会主动取消这一轮。帮助弹窗采用原生 dialog，关闭只关闭说明，不退出当前设置或聊天。

两个宿主都读取 `OSContext.characters`，保存都调用 `updateCharacter(id, prev => ({ activeMsg2Config: updater(prev.activeMsg2Config) }))`，不会持久化第二份开关。即时对话和开启主动消息立即保存；关闭主动消息沿用原「关闭 2.0」提交与云端清理，未提交时提示关闭尚未保存，不能把表单草稿当作两处已同步的关闭状态。角色关闭「聊天 · 时间感知强化」时，开启主动消息 2.0 会先展开内联确认卡片说明现实定时与架空剧情时间可能错乱，用户明确确认（`allowWithoutTimeAwareness`）后才开启；在神经链接关闭聊天时间感知时，若角色已启用 2.0，默认引导同步停用并清理云端排期（`utils/amsg2TimeAwarenessGate.ts`），恢复时间感知或停用 2.0 时清除确认标记。

云端管理遵守 `plans/amsg2-cloud-data-management-contract.md`：实际资源清单、持久清理操作、停用与恢复的代次均不改变。普通文件导出默认不带后台连接，用户可以勾选用于自己换机；个人 GitHub / WebDAV 云端备份显式带上连接，不受文件导出的脱敏偏好影响。单用户及多用户的文字／完整包都保留原 userId、地址、密钥、全局开关、通知渠道配置和角色设置／任务记录。媒体补图包仍不恢复文字配置。配置读取失败会中止备份，不再跳过后显示成功。

单用户配置位于 ZIP 的 `metadata.json` 中的 `amsg2GlobalConfig`，多用户包位于 `user-spaces.json` 的 `backend`；角色配置在各自的角色记录中。恢复仍需明确同意接回后台，不克隆本设备推送订阅、不重建任务；服务器中的任务执行状态仍以原后台为准。旧备份中已经缺失的连接无法凭空补回，需要原设备重新备份或另行生成连接码。

## 全局总开关

填写过 Worker 地址后，设置页「主动消息 2.0」卡片显示**总开关**；连接完成后，工作区默认进入的功能总览也集中提供这个开关（`ActiveMsg2GlobalConfig.enabled`，未设置时视为开启；编排在 `utils/amsgGlobalSwitch.ts`，判断统一走 `utils/amsgGlobalGate.ts`）。未连接时总览的两个开关置灰并提供连接入口，不伪装成已经启用。

- **保留配置就地暂停**：关闭总开关只把 `enabled` 存为 `false`，Worker 地址、共享密钥、主密钥、中转设置、推送方式以及各角色自己的开关与任务清单全部原样保留，恢复开启即可继续使用，不必重新填地址或重配角色。
- **本机零残留请求**：总开关关闭期间，冷启动、回到前台、第三方推送前台轮询、晚投情绪轮询、聊天与见面的活跃会话租约、记忆宫殿门牌云端通道、离开后消息与见面离开提醒的云端分支、工具与 API 凭据同步、角色上下文（`fire_pack`）上传，以及打开设置页 / 推送面板 / 角色 2.0 面板时的自动探测，一律不在后台向 Worker 或中转服务发起请求。即时对话自动回退到本机生成。
- **远端定时触发尽力暂停、绝不阻塞本地关闭**：关闭瞬间会先切断本机在途等待与定时器，再以短超时尝试通知 Worker 摘掉 Cron 定时触发并取消在途即时任务。即使 Worker 已被删除、断网或缺少 `CF_API_TOKEN`，本机暂停依然立即完成，只在界面提示云端定时触发未能同步暂停。
- **暂停期间的改动记账延后对齐**：暂停时修改工具配置、API Key 或角色资料，本地待同步标记会保留在 `localStorage` 中，不发请求也不排退避重试；暂停期间删除角色或用户空间，不阻塞删除流程，而是把角色记入本机待停用底账（`amsg2_cloud_retirements`）。重新开启总开关（或点击「连接并启用」）后，系统自动恢复定时触发，并依次补送待停用角色、订阅变化标记、云端漏收账本与待同步快照。
